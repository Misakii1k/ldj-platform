4. 本轮修复的 3 个焦点缺陷

4.1 模态弹层内 Tab 焦点每轮停在 <body>

现象：弹层打开时按 Tab，每循环一次就有一站落在 body 上——焦点环消失，读屏位置丢失。

根因（已用最小对照页证明是浏览器原生行为，不是测试假象）：一个不含任何自定义脚本的 <dialog> + showModal() 页面，Tab 轨迹为 body → #close → body → #close → …。影响榴莲全部 3 个弹层与狼人杀共用的 #dialog。

修复：为每个弹层加显式 Tab 循环（首尾相接、跳过 disabled 与不可见元素）。 durian.js:142 新增 trapFocus()，durian.js:176 应用于所有 .d-dialog；art-directions.js:22 为共用弹层加同样的处理。

复验：榴莲 Tab 轨迹不再出现 body；狼人杀弹层内 Tab 10 次始终停留在弹层内。

4.2 榴莲点「确认出牌」后焦点丢失

现象：点击确认后阶段切到 waiting，被点击的按钮随即被重新渲染销毁，document.activeElement 掉到 body。

修复：durian.js:112 的 place() 在渲染完成后，把焦点交给新阶段第一个可用按钮（看牌列），与该文件既有做法一致。

复验：断言「确认出牌后焦点不丢到 body」由失败转为通过。

4.3 狼人杀点「结束发言」后焦点丢失

现象：推进到下一位发言者后，#finish 变为 disabled，焦点无处可去而掉到 body，键盘用户失去上下文。

修复：art-directions.js:43 推进后把焦点移到新的发言人标题；art-directions.html:14 为该标题加 tabindex="-1"。

复验：断言「推进后焦点落到新发言人」通过。

4.4 需要更正的上一轮判断

本轮批量脚本最初报告"狼人杀 4 个弹层关闭后焦点未回到触发元素"。该结论是测试假象：脚本用的是程序化 element.click()，它不会移动焦点，导致弹层打开时记录的"触发元素"其实是 body。

改用真实鼠标点击 / 键盘 Enter 复测后，焦点均正确回到触发元素（#rules、#identity、#ledger、席位按钮四种场景全部通过）。另用无自定义代码的最小对照页确认，Chromium 原生已具备关闭后回焦能力。

因此：art-directions.js:19/45 中补充的显式回焦并非修复 Chromium 缺陷，而是为 iOS Safari 等未真机验证的环境留的跨浏览器保险。若认为原型应保持最小改动，这两处可以移除，Chromium 下行为不变。

6.0 对上一版报告的更正

本报告上一版有两处结论不准确，现已更正：

  • 原写"844×390 紧凑模式需滚动约 93px" —— 该问题已在本轮修好（见 6.1），现为"一屏放下"。
  • 原写"1280×800 舒展模式全部在屏内，无滚动容器" —— 这是错的。当时的判定只看元素可见性，没有逐元素测内部滚动量，也没有察觉底部粘性操作条会盖住正文。实测 main.d-game 需滚动 76px，且「桌面累计需求」在初始滚动位置会被粘性操作条遮住大半。上一版之所以得出错误结论，正是因为依赖了被 body{overflow:hidden} 夹住的 documentElement.scrollHeight。本轮已改为逐元素测量。
  • 榴莲舒展模式仍需滚动：360×640 需 127px、1280×800 需 76px；390×844 与 844×390 为一屏。这与 DESIGN.md「舒展模式为 2 列 × 3 行，可能需要少量滚动」的既有约定一致。默认的紧凑模式在四种视口全部一屏放下，符合"尽量一屏展示"的偏好。是否进一步压缩舒展模式由你决定。
  • 未做真机验证：以上全部为桌面 Chromium 模拟视口的结论，未在 iOS / Android 真机上测过触控、刘海安全区与软键盘。
  • Georgia 缺失环境未测：Georgia 为系统字体，缺失时回退 Times New Roman/serif，字宽会有差异。
  • 狼人杀只验收了白天发言场景：art-directions.html 仍是发言场景候选稿，夜晚与投票的完整交互仍在早期 werewolf.html，本轮未验收。
  • 本报告不代表正式接入已就绪：未改动 packages/client/** 任何生产代码，未做协议、构建与业务联调。接入差异见 integration-diff.html。

6.1 本轮修复：短横屏不再需要滚动

根因：在短横屏断点下 .d-layout 被设为两列（durian-fit.css:26），但它的第二个子元素 .d-play-area 早已移进回合弹窗，.d-layout 只剩 .d-players-area 一个孩子——整个第二列是空的。与此同时「桌面累计需求」被压在下方，恰好多出 93px。

修复（durian-fit.css，新增 max-height:520px and min-width:640px 块）：把空的第二列真正用起来，让 .d-players-area 在该断点变成两列网格，把「桌面累计需求」移进右列；同时把该断点原先被 display:none 隐藏的水果名恢复显示。

结果：844×390 与 640×390 的紧凑与舒展模式全部一屏放下（溢出 0），且水果名比修改前显示得更完整。全程没有缩小任何字号，也没有把任何触控目标压到 44px 以下。
