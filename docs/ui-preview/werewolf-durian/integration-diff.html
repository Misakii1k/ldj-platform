3.3 隐藏信息隔离（原型做对了，但要换成服务端来源）

  • 公共视图刻意排除 state.deck（只给 deckCount）、state.foreheadCards（整表不出）、state.drawnCard；隔离点就在 views.ts:110-130 的返回字面量。
  • 观战者 me: null（views.ts:137-142），因此每个座位都渲染"未知手牌"暗牌（DurianGamePage.tsx:763-775）。
  • schema 用 .strict() 拒绝多余字段（schemas.ts:67-105），views.test.ts:31-37 断言多余字段抛 /字段无效/。
  • 原型侧我已加结构性断言（内容区不得渲染手牌类节点）。接入时这条断言应转为服务端视图测试，而不是前端扫描 DOM。

3.4 一个容易搞错的点：库存也是私密信息

全桌"实际库存"是由所有人的头顶牌加总得出的。原型因此刻意不显示库存与超卖，只显示累计需求。接入时若有人想在大屏上加"库存/超卖提示"，那会直接泄露隐藏信息——不要加。

3.5 生产已有、原型没有

  • 「📺 公共大屏」徽标（DurianGamePage.tsx:414-418）与隐藏 ActionDock（:439-445）——原型有等价物，需并入既有类名体系。
  • 模拟模式还有"面前立牌"分支（:692），原型未覆盖。

8. 不可直接迁移的项（避免误判）

  • 生产 stacked 的语义：它是"图标叠放"开关，不等于"数量在水果下方"。数字显示由独立的 showBadge 控制（详见 2.2）。

  • 原型的 12 人狼人杀：生产抽卡 5–12 人（v2 6–12），席位数量可变。
  • 原型的质疑结算是手动"开始下一轮"：生产 standard 模式是倒计时自动推进，语义不同。

9.2 端到端：28 失败 / 61 通过 —— 这是接入前最需要处理的阻塞项

失败不是环境问题，可归为两类根因：

不是"应用路由错"，而是电脑端作为主机时：初次访问默认先展示主机控制台大屏这一新行为：

// packages/client/src/app/AppModeContext.tsx:58-65
const [showHostConsole, setShowHostConsole] = useState(() => {
  if (isNativeApp() || !isLocalhostOrigin()) return false;

e2e 用 127.0.0.1:3178（localhost）+ Playwright 每个 spec 独立 context（sessionStorage 为空），因此 isPcHost=true && showHostConsole=true，总是落在「聚乐桌游 电脑主机大屏」页。渲染入口见 AppModeContext.tsx:115：else if (isPcHost && showHostConsole)。
