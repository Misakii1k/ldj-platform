# 05 争议与待确认

## 1 规则书核对项

| 事项 | 已知 | 待确认 |
|---|---|---|
| 人数、时长、年龄 | 官方页为 2–7 人、20 分钟、7+ | 无 |
| 组件 | 官方页列出 28 水果卡、3 猩猩卡等 | 不同印次是否变更 |
| 库存发放 | 每人一张且本人不可见，另有未知卡 | 不同人数精确发牌/移除规则 |
| 按铃资格 | 核心说明支持在超卖时按铃 | 是否仅当前玩家、准确时间窗 |
| 被质疑对象 | 通常是上一位接单者 | 首回合与换轮边界 |
| 超卖判定 | 订单大于库存 | 特殊卡修正顺序 |
| 怒气 | 由 1 逐步升至 7 | 递增时点、个人轨道含义 |
| 结束与胜者 | 某玩家可能在高怒气时一次输掉 | 达到/超过阈值、并列胜负 |
| 3 张猩猩卡 | 官方确认存在 | 每张准确效果与触发时机 |
| 新一轮起始者 | 检查后重置 | 谁先行动、方向是否变化 |

## 2 高风险误解

“能看到其他人库存”不等于知道总库存，因为自己的卡和未知卡无法查看。“订单等于库存”也不构成超卖，只有严格大于才成立。数字版若用红色警告、自动概率或库存区间提示，会破坏原本的不完全信息判断。

按铃对象与按铃资格直接影响策略。若把“当前玩家质疑上一位”改成“任何人随时抢铃”，网络延迟和反应速度会替代部分推理，因此必须作为独立变体。

## 3 猩猩卡

当前目录不臆造 3 张特殊卡的效果。开发前必须录入目标规则书原文含义、数值、持续时间、与未知库存的互动以及检查时的计算顺序。测试用例需要为每张卡单独覆盖成功和失败质疑。

## 4 数字化决策

1. 是否保留实体铃的抢按感。建议使用当前行动者专属按铃窗口，除非官方规则明确允许抢铃。
2. 是否设置回合超时。建议休闲房 45 秒，超时自动选择策略由房主预先决定。
3. 是否允许撤回订单选择。建议提交前可改，提交后不可撤销。
4. 检查动画是否可跳过。建议个人可加速，但全房在结果确认点同步。
5. 复盘是否公开个人此前看不到的库存。建议轮次结束后公开，便于理解误判。

## 5 版本与本地化

官方商品页显示日英版与英/西/德/法等说明书组合。中文名称、中文规则和卡牌术语可能来自代理版或玩家翻译，必须指定采用哪一版本。水果名称应统一，避免同一水果在订单板、卡面和结算中出现不同译名。

## 6 版权

设计者、插画师、出版商和发行年份可按官方信息署名，但署名不等于获得数字改编授权。数字化组件、美术、音效、商标使用和规则文本复制均需独立确认。若只做内部原型，应限制传播并清楚标注非官方。
