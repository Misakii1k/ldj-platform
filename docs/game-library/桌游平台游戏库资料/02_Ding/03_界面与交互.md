## 核心页面（D 级 — 设计建议）

### 1. 大厅页面 Lobby

| 元素 | 说明 |
|------|------|
| 房间码 | 显示当前房间编号，供其他玩家加入 |
| 玩家列表 | 显示已加入玩家的头像和昵称 |
| 准备按钮 | 每位玩家准备就绪后，房主可开始游戏 |
| 设置选项 | 回合数/分数上限/铃铛模式切换等（待确认） |
| 开始按钮 | 房主专用，所有玩家准备后启用 |

交互原则：
- 2-7 人可加入
- 房主可调整游戏参数（待确认）
- 提供清晰的退出机制

### 2. 游戏主页面 Game Board

| 区域 | 说明 |
|------|------|
| 卡牌展示区（中央） | 展示本轮卡牌，所有玩家同步看到相同内容 |
| 玩家信息区（侧边/底部） | 显示各玩家分数、状态 |
| 抢答按钮/区域 | 玩家点击/触摸抢答的交互区域 |
| 回合信息 | 当前回合数/总回合数（待确认） |
| 计时器 | 反应窗口倒计时（待确认） |

交互原则：
- 所有玩家同步看到卡牌翻转
- 卡牌展示后立即进入可抢答状态
- 抢答应有明确的视觉反馈（按钮亮起/音效提示）
- 抢答后需给出答案（可能是点击对应图案/颜色，待确认）
- 结果反馈应清晰区分正确与错误

### 3. 结算页面 Result

| 元素 | 说明 |
|------|------|
| 排名列表 | 按最终分数从高到低排列 |
| 统计数据 | 正确次数、错误次数、平均反应时间等（待确认） |
| 再来一局按钮 | 返回大厅重新开始 |
| 退出按钮 | 离开当前房间 |

### 4. 设置页面 Settings（待确认）

是否需要独立的设置页面取决于游戏参数复杂度。可能包含：
- 回合数 / 目标分数
- 铃铛模式开关
- 反应窗口时长
- 音效/震动开关

## 交互原则（D 级 — 设计建议）

1. **低延迟优先**：抢答类游戏对网络延迟极为敏感，交互设计需考虑延迟补偿。
2. **明确的反馈**：每次操作（抢答、判定、结算）都应有即时的视觉和/或听觉反馈。
3. **公平性**：所有玩家必须同时看到卡牌，防止先发优势。服务器端进行时间戳校正。
4. **防误触**：在非抢答阶段应禁用抢答按钮，防止误操作。
5. **容错性**：网络断线重连后，应能恢复当前游戏状态。
6. **无障碍**：考虑色盲玩家，不应仅依赖颜色作为唯一判断依据。

## 关于铃铛交互的特殊说明（待确认）

如果游戏支持铃铛模式：
- 物理铃铛：玩家敲击实体铃铛，系统通过麦克风或专用设备检测（待确认实现方式）
- 虚拟铃铛：屏幕上的铃铛按钮，点击抢答（待确认）

如果采用无铃铛模式：
- 可能是点击屏幕/按钮抢答
- 也可能是喊出答案后由系统语音识别判定（待确认）
