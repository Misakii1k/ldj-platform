## 通用引擎流程（D 级 — 设计建议）

以下流程基于同类游戏（如《闪灵快手》《德国心脏病》《嗒宝》等）的通用机制推导，**并非 Ding 的官方规则**，仅作为抢答类游戏引擎的参考架构。

```
┌─────────────────────────────────────────────────────┐
│                   通用抢答引擎流程                      │
├─────────────────────────────────────────────────────┤
│  1. 同步翻牌阶段                                       │
│     → 系统向所有玩家同步展示本轮卡牌                     │
│  2. 逻辑反应窗口开放                                    │
│     → 玩家开始观察卡牌，进入可抢答状态                    │
│  3. 玩家抢答                                           │
│     → 玩家通过点击/触摸/敲击等方式触发抢答                │
│  4. 服务器校正时间                                      │
│     → 服务端验证抢答顺序，确定最先抢答者                   │
│  5. 验证触发条件                                        │
│     → 检查抢答者的答案是否正确（卡牌是否满足触发条件）       │
│  6. 成功/错误结算                                       │
│     → 正确：加分/取得优势；错误：扣分/惩罚                  │
│  7. 下一轮或终局判断                                     │
│     → 检查是否达到终局条件；若是则进入结算，否则开始新一轮    │
└─────────────────────────────────────────────────────┘
```

## 待确认规则清单

| 序号 | 待确认项 | 优先级 | 备注 |
|------|----------|--------|------|
| 1 | 卡牌类型与数量 | 高 | 需要牌表 |
| 2 | 每回合翻牌方式 | 高 | 单张/多张？是否同时翻？ |
| 3 | 触发条件定义 | 高 | 什么图案/颜色/组合算匹配？ |
| 4 | 抢答方式 | 高 | 铃铛/按钮/其他？ |
| 5 | 计分规则 | 高 | 每回合得分？胜利分数？ |
| 6 | 错误惩罚 | 中 | 扣分/跳过回合/其他？ |
| 7 | 终局条件 | 中 | 达到多少分？时间限制？ |
| 8 | 特殊卡牌效果 | 中 | 是否有功能卡/万能卡？ |
| 9 | 铃铛版本差异 | 低 | 是否必须使用铃铛？ |
| 10 | 玩家数量影响 | 低 | 不同人数规则是否调整？ |
