## 2. 状态机设计

### 2.1 游戏阶段状态

`
[LOBBY] --> [ROLE_DEAL] --> [CASE_VIEW] --> [PASSING] --> [ACCUSATION] --> [VOTE] --> [RESULT] --> [LOBBY]
`

### 2.2 各状态说明

| 状态 | 含义 | 可执行操作 |
|------|------|-----------|
| **LOBBY** | 游戏大厅 | 加入/离开/准备/开始游戏 |
| **ROLE_DEAL** | 分配角色 | 系统分配角色（头鹅 + 恶鹅 + 白鹅） |
| **CASE_VIEW** | 头鹅查看案情 | 头鹅阅读案情卡（其余玩家闭眼/屏敝） |
| **PASSING** | 表演传递 | 逐棒进行肢体表演传递 |
| **ACCUSATION** | 指认阶段 | 玩家猜测案情内容（方式待确认） |
| **VOTE** | 投票阶段 | 玩家投票选出恶鹅（是否启用待确认） |
| **RESULT** | 结果展示 | 公布原始案情、传递结果、胜负判定 |

### 2.3 传递子状态机

`
PASSING:
  [WAITING_PERFORMER] --> [PERFORMING] --> [WAITING_OBSERVER] --> [NEXT_TURN]

  - WAITING_PERFORMER: 等待当前表演者准备就绪
  - PERFORMING: 表演者正在进行肢体表演（计时器？待确认）
  - WAITING_OBSERVER: 等待观察者确认已理解表演
  - NEXT_TURN: 切换至下一对表演者-观察者
`

## 4. 数据约束

- 案情内容必须包含至少一个凶手鹅和一个受害鹅（B/C 级）
- 表演传递过程中不允许文字或语音辅助（B/C 级）
- 角色分配必须在游戏开始前完成，不可中途变更（D 级）
- 上述所有约束均需通过 A 级来源验证后方可视为正式规则
