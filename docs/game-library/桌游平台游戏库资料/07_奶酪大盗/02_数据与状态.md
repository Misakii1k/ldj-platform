# 02 数据与状态

## 1 核心实体

| 实体 | 关键字段 | 可见范围 |
|---|---|---|
| 房间 | 房间号、规则版本、人数、房主、语音配置 | 房内公开 |
| 玩家 | 玩家编号、座位、昵称、连接状态、是否准备 | 房内公开 |
| 私有骰子 | 点数 1–6、生成时间、是否已确认 | 仅本人及权威服务器 |
| 奶酪 | 在中央、已被取走、持有者、被取走时刻 | “是否在桌面”按阶段可见；持有者仅服务器/小偷 |
| 夜晚时刻 | 当前时刻、该时刻醒来玩家集合 | 当前醒来者与服务器 |
| 夜间观察 | 观察者、时刻、同醒者、奶酪当时状态 | 仅观察者；赛后按配置公开 |
| 讨论 | 开始时间、剩余时间、发言状态 | 房内公开 |
| 指认 | 投票者、目标、锁定状态 | 结算前仅本人及服务器 |
| 结算 | 小偷、真实时刻链、票型、胜方 | 赛后公开范围待确认 |

## 2 状态机

推荐阶段顺序：`等待加入 → 准备确认 → 私密掷骰 → 记忆确认 → 夜晚封闭 → 时刻1…时刻6 → 天亮 → 讨论 → 指认 → 结算 → 再来一局`。

每次阶段迁移由服务器决定。客户端按钮只能提交意图，不能自行宣布进入下一时刻。夜间每个时刻至少包含“准备遮罩、私有展示、结束遮罩”三个内部状态，以防动画和真实数据切换不同步。

## 3 权威结算数据

服务器需保存原始骰点映射，并按骰点构造醒来组。按 1 至 6 遍历：

- 醒来组为空：奶酪状态不变。
- 醒来组人数大于 1：为每名成员生成同醒者观察；奶酪状态不变。
- 醒来组人数等于 1，且奶酪在中央：将奶酪持有者设为该玩家，并记录盗取时刻。
- 醒来组人数等于 1，但奶酪已失踪：只记录该玩家观察到奶酪缺失。

该模型是对核心机制的数字化表达。若最终规则书规定多人醒来时仍存在可选动作、特殊角色或特殊人数规则，必须调整。

## 4 可见性矩阵

| 信息 | 夜晚闭眼者 | 当前醒来者 | 白天全体 | 赛后 |
|---|---:|---:|---:|---:|
| 自己骰点 | 可见或可回看 | 可见 | 建议仅本人 | 可公开 |
| 他人骰点 | 不可见 | 不可见 | 不可见 | 建议公开 |
| 当前时刻 | 不给出精确提示或仅给通用进度 | 可见 | 不适用 | 可公开 |
| 同时醒来者 | 不可见 | 可见 | 由玩家口述 | 可公开 |
| 奶酪当时状态 | 不可见 | 可见 | 由玩家口述 | 可公开 |
| 小偷身份 | 不可见 | 小偷本人可知 | 不公开 | 公开 |
| 投票内容 | 不可见 | 不适用 | 提交者本人可见 | 公开票型或仅结果待确认 |

## 5 随机与审计

骰点必须使用不可由房主操纵的服务端随机源。为排查争议，可记录局号、随机过程版本和不可篡改的事件序列，但普通玩家不应在局中接触种子。若平台提供“公平性证明”，只能在结算后披露足以验证而不能预测下一局的信息。

## 6 重连与异常

- 私密掷骰后重连：恢复本人骰点，不重掷。
- 夜晚中重连：先显示闭眼遮罩；若本人当前正在醒来窗口，可恢复剩余窗口，但不能补看已错过的其他时刻。
- 讨论中重连：恢复自己的私人笔记和公开计时，不自动公布夜间记录。
- 投票提交后重连：恢复“已提交”状态；是否允许改票按房规。
- 服务器中断：无法证明状态连续时应宣布本局无效，不能客户端多数表决还原隐藏信息。

## 7 数据留存建议

长期统计只保留局数、胜负、角色和时长等必要数据。夜间观察与完整语音涉及社交内容及隐藏信息，默认不永久保存；录像或语音存储须另行征得同意。赛后复盘数据应在整局结束后一次性解锁，避免淘汰者提前泄密。
