# AI 引擎设置渐进式优化设计

## 目标

将当前 AI 引擎长表单升级为渐进式配置体验，让首次配置者能够快速完成连接，同时保留自定义网关、本地模型、推理参数和预设管理等高级能力。新增真实模型调用诊断，使用户在保存前能够确认地址、密钥和模型是否实际可用。

## 成功标准

- 用户通过内置预设、API Key 和模型三个核心步骤即可完成常见云服务配置。
- 高级字段默认不占据主要视觉层级，但可随时访问且不损失现有能力。
- 用户可以使用当前未保存表单执行最小真实模型调用，并获得延迟和可操作的失败原因。
- 连接测试是可选操作，不阻断直接保存。
- 已保存 API Key 继续只进不出，诊断接口不泄露密钥、上游正文或内部错误。
- 现有设置、预设、模型目录和管理员口令行为保持兼容。

## 范围

### 包含

- 重构 AI 引擎设置区的信息架构和交互层级。
- 增加当前运行状态、诊断状态和配置变化提示。
- 增加基础设置、模型与推理、高级选项三个页签。
- 增加可搜索模型选择和手动模型输入切换。
- 改进预设的新建、选择和删除规则。
- 新增服务端真实连接诊断接口及稳定错误分类。
- 补充客户端纯状态测试、服务端接口测试和浏览器验收。

### 不包含

- 不更改 AI 玩家实际决策策略或提示词。
- 不增加请求历史、Token 用量统计、费用分析或远程监控。
- 不增加配置导入导出、批量诊断或独立设置工作台。
- 不重构背景和动效设置区域。
- 不将诊断结果持久化到数据库。

## 选定方案

采用渐进式配置方案，而不是继续扩展单页长表单或建设独立设置工作台。

- 单页精简改动较小，但高级参数和预设管理仍会持续挤压主要流程。
- 独立工作台扩展性最好，但与当前产品规模不匹配，增加不必要的导航和维护成本。
- 渐进式配置能让高频操作先行，高级能力按需展开，在新手易用性和专业控制之间最平衡。

## 信息架构

AI 引擎区域按以下顺序呈现：

1. 当前运行状态。
2. 快捷预设。
3. 快速连接。
4. 基础设置、模型与推理、高级选项三个页签。
5. 当前页签内容。
6. 全局错误和保存操作。

### 当前运行状态

顶部状态条展示：

- 当前服务商。
- 当前模型。
- 是否已经保存 API Key。
- 最近一次连接诊断状态。
- 当前表单是否已偏离最近诊断配置。

状态条不展示 API Key 原文、上游响应正文或内部错误堆栈。

### 快捷预设

保留 DeepSeek 官方、Anthropic Claude 和本地 Ollama 三个内置预设。内置预设不可删除，自定义预设可删除。

选择预设后立即填充服务商、Base URL、模型、思考深度和建议超时，但不自动保存、不自动测试。删除当前自定义预设仅移除预设，不清空当前表单。

### 快速连接

快速连接区域包含：

- 当前预设或服务商摘要。
- API Key 输入与已保存状态。
- 测试连接按钮。
- 保存并启用按钮。

测试连接与保存互相独立。测试期间只禁止重复测试，不锁定整个表单。

### 页签

#### 基础设置

- 服务商协议。
- API Key。
- 模型选择或手动模型输入。

#### 模型与推理

- 模型目录刷新。
- 可搜索模型选择器。
- 手动输入模式。
- 思考深度。
- 单次决策超时。

#### 高级选项

- Base URL。
- 管理员口令。
- 清除已保存 API Key。
- 当前配置来源说明。

## 模型选择

获取模型目录成功后，展示支持文本过滤的模型列表。用户始终可以切换为手动输入，以兼容没有模型目录接口或返回非标准目录的服务。

更改服务商或 Base URL 时清空旧的模型目录结果，但保留当前模型文本。目录请求失败时显示明确原因和常用模型建议，不阻断保存。

## 连接诊断

新增 `POST /api/settings/llm/test`。该接口使用当前未保存的表单配置执行最小真实模型调用。

### 请求

请求体包含：

- `provider`
- `baseUrl`
- `model`
- `thinkingDepth`
- `timeoutMs`
- 可选 `apiKey`

如果请求未包含 `apiKey`，服务端复用当前已保存密钥；显式传入 `null` 表示不使用密钥。接口沿用设置写入接口的管理员口令鉴权。

### 上游调用

- OpenAI 兼容协议调用 Chat Completions。
- Anthropic 协议调用 Messages。
- 使用固定最小提示，要求模型只回复 `OK`。
- 不发送房间、玩家、对局、设置或其他业务数据。
- 使用很小的输出 Token 上限和零或最低随机性。
- 超时读取当前表单值，同时限制在服务端允许范围内。

### 成功响应

```json
{
  "status": "ok",
  "provider": "openai",
  "model": "deepseek-chat",
  "elapsedMs": 820,
  "usedSavedApiKey": true,
  "message": "模型响应正常"
}
```

成功只要求上游返回符合对应协议的非空文本，不把模型原始回复返回客户端。

### 失败分类

- `INVALID_CONFIG`：地址、模型、协议或超时配置无效。
- `AUTH_FAILED`：API Key 无效或权限不足。
- `MODEL_NOT_FOUND`：模型不存在或不可访问。
- `RATE_LIMITED`：上游限流。
- `UPSTREAM_TIMEOUT`：上游超时。
- `UPSTREAM_UNAVAILABLE`：网络错误或上游服务不可用。
- `INVALID_RESPONSE`：HTTP 成功但响应结构不符合所选协议。

客户端将错误码映射为明确建议，不直接展示上游响应正文。

## 诊断状态模型

客户端诊断状态为：

- `idle`：尚未测试。
- `testing`：正在测试。
- `success`：当前关键配置测试成功。
- `stale`：测试后修改了关键配置。
- `error`：测试失败。

关键配置由服务商、规范化 Base URL、API Key 输入状态、密钥清除状态、模型、思考深度和超时组成。任一关键字段变化后，已有成功或失败结果变为 `stale`，并显示“配置已变化，建议重新测试”。

关闭设置弹层时终止未完成的模型目录请求和诊断请求，避免卸载后更新状态。

## 组件边界

为避免继续扩大现有 `SettingsSheet`，AI 设置拆分为：

- `AiEngineSettings`：AI 设置数据、保存、目录请求和诊断流程的容器。
- `AiEngineStatus`：运行状态和诊断摘要。
- `AiProfilePicker`：预设选择、新建和删除。
- `AiQuickConnect`：API Key、测试和保存主操作。
- `AiSettingsTabs`：页签语义和切换。
- `AiModelPicker`：模型搜索、选择、刷新和手动输入。
- `AiConnectionTestResult`：测试中、成功、过期和错误反馈。
- `aiSettingsState.ts`：表单规范化、关键字段指纹、诊断状态转换和错误映射纯函数。

`SettingsSheet` 继续负责弹层、背景设置和动效设置，只装配 `AiEngineSettings`，不再持有 AI 表单的全部细节。

## 保存行为

- 连接测试是可选操作，未测试或测试失败都不阻断保存。
- 保存前执行客户端基础校验，服务端继续执行权威校验。
- 保存成功后刷新顶部运行状态，清空新输入的 API Key，并将诊断结果与已保存配置对齐。
- 保存失败时保留全部表单内容和诊断结果。
- 输入新 API Key 表示替换；默认不回显已保存密钥。
- 清除密钥位于高级选项，要求二次确认。

## 安全设计

- API Key 仍保持只进不出。
- 诊断请求体、日志和错误消息不记录密钥。
- 服务端不返回上游响应正文、请求正文或堆栈。
- 管理员口令沿用现有 `x-admin-token`，不持久化到服务端。
- 诊断结果只保存在当前客户端组件状态。
- 服务端对 URL 协议、字段长度、超时范围和响应体大小执行限制。
- 诊断请求使用 AbortController，并在超时或客户端断开时终止上游调用。

## 错误处理

- 表单错误显示在对应字段附近，并在区域顶部提供摘要。
- 模型目录失败不影响手动模型输入和保存。
- 诊断失败显示错误类别、简短说明和下一步建议。
- 管理员口令缺失时沿用现有授权输入流程。
- 网络中断、请求取消和上游超时使用不同提示。
- 多次点击测试只保留一个活动请求；新测试开始时取消旧测试。

## 响应式与无障碍

- 桌面端快速连接采用双列布局，移动端改为单列。
- 页签使用 `tablist`、`tab` 和 `tabpanel`，支持左右方向键切换。
- 状态同时使用图标和文字，不仅依赖颜色。
- 测试状态使用非打断式实时区域播报。
- 密钥支持显示或隐藏，但不写入额外 DOM 属性。
- 所有按钮和可点击区域至少 44×44px。
- 错误与帮助文本通过 `aria-describedby` 关联字段。

## 测试策略

### 纯函数测试

- 表单规范化。
- 关键配置指纹。
- 诊断状态从成功或失败变为过期。
- 服务端错误码到客户端建议的映射。
- 非法响应回退。

### 服务端测试

使用本地模拟上游覆盖：

- OpenAI 兼容成功响应。
- Anthropic 成功响应。
- 复用已保存 API Key。
- 显式替换和显式清除 API Key。
- 管理员鉴权。
- 401/403 鉴权失败。
- 404 模型不存在。
- 429 限流。
- 超时和网络失败。
- HTTP 成功但响应 JSON 非法或结构错误。
- 响应不包含密钥和上游正文。

### 浏览器验收

- 内置与自定义预设切换。
- 三个页签的键盘操作。
- 模型目录搜索和手动输入。
- 已保存密钥复用、新密钥替换和清除确认。
- 连接成功、失败、测试中和配置过期状态。
- 未测试直接保存。
- 管理员口令场景。
- 移动端单列布局和 44px 触控目标。

## 兼容与回滚

- 保留现有 `GET /api/settings/llm`、`PUT /api/settings/llm` 和 `POST /api/settings/llm/models` 协议。
- 不修改数据库字段或已有设置键。
- 新诊断接口是增量能力，旧客户端不受影响。
- UI 重构通过组件装配完成，可回滚到原 AI 设置区而不影响服务端已保存配置。
- 内置预设结构继续兼容现有服务端预设摘要格式。
