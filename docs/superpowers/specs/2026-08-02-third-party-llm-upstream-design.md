# 第三方大模型上游连接修复设计

## 目标

修复第三方大模型配置链路，确保连接测试、模型目录发现和真实对局决策使用一致的协议与安全规则；模型目录只展示上游真实提供的模型 ID；新增原生 `max` 思考深度并兼容旧 `8192` 配置。

## 成功标准

- 公网第三方服务、本机 Ollama、局域网 vLLM 和自建 OpenAI 兼容网关可在明确安全策略下实际用于 AI 玩家决策。
- 同一份有效配置在连接测试成功后，真实对局使用相同的 URL、鉴权、请求参数和响应解析规则。
- 模型目录只返回上游响应中的合法模型 ID，不再把内置建议伪装成远程结果。
- 用户仍可手动输入不提供模型目录接口的模型 ID。
- 思考深度支持 `off / low / medium / high / max`，旧 `8192` 自动兼容为 `max`。
- 上游不支持 `max` 时返回明确错误，不静默降级。
- API Key 不因重定向、日志或错误响应泄露。

## 范围

### 包含

- 统一 OpenAI 兼容协议与 Anthropic 协议的端点、请求体、鉴权和响应解析。
- 让连接诊断与真实对局调用复用统一协议适配逻辑。
- 加固真实对局上游请求的 URL 校验、重定向、超时和响应大小限制。
- 收紧模型目录 ID 解析并移除伪成功回退。
- 支持标准模型目录分页，同时限制页数和结果数量。
- 新增 `max` 思考深度并迁移旧 `8192` 配置。
- 补充服务端、共享契约和客户端状态测试。

### 不包含

- 不新增除 OpenAI 兼容协议和 Anthropic 协议以外的供应商插件。
- 不建设完整模型能力数据库。
- 不改变 AI 玩家提示词、候选动作约束或规则回落策略。
- 不增加 Token 用量、费用统计或调用历史。
- 不删除手动模型 ID 输入能力。

## 选定方案

采用统一上游适配层，而不是分别修补连接测试、模型目录和真实对局三条请求链路。

统一层负责协议相关行为，安全上游层负责地址、重定向、取消和响应体限制。连接测试与真实对局仅提供不同的提示内容和输出解析目标，从而消除两份实现漂移。

## 架构

### 协议适配层

新增聚焦协议行为的模块，提供以下能力：

- 根据 provider 和 Base URL 构造推理端点与模型目录端点。
- 构造 OpenAI Chat Completions 或 Anthropic Messages 请求。
- 映射思考深度参数。
- 提取文本响应。
- 解析和规范化模型目录结果。
- 将可识别的上游状态转换为稳定错误分类。

适配层不读取数据库、不管理 React 状态，也不决定私网地址是否允许。

### 安全上游层

扩展现有安全请求能力，使连接测试、模型目录和真实对局共同使用：

- 仅允许 `http` 和 `https`。
- 公网 HTTPS 默认允许。
- 本机与局域网地址通过服务端明确配置放行。
- 请求使用 `redirect: manual`，不自动把鉴权头带到重定向目标。
- 响应 JSON 使用统一大小上限。
- 支持调用方超时和客户端断开取消。
- 日志只记录稳定事件、状态码、耗时和业务元数据，不记录密钥、上游正文或完整异常详情。

### 调用方

- 连接测试使用固定最小提示，只验证端点、鉴权、模型和思考参数是否可用。
- 真实对局使用现有桌游提示和候选动作，失败时继续返回 `null` 并触发规则策略回落。
- 模型目录只负责发现 ID，不依赖思考深度。

## 地址策略

公网第三方服务与本地服务采用显式区分：

- 公网 HTTPS 端点按现有 URL 校验直接使用。
- `localhost`、回环地址和私网网段默认不由任意远程请求访问。
- 服务端增加明确的本地上游允许配置，用于部署者启用 Ollama、vLLM 或局域网网关。
- 允许私网上游后仍执行端口、协议、重定向和响应大小约束。
- 不提供完全绕过安全校验的对局专用路径。

## 模型目录

### 请求

- OpenAI 兼容协议和 Anthropic 协议默认调用规范化后的 `/v1/models`。
- Base URL 已是 `/models` 或 `/v1/models` 时不重复拼接。
- 使用与推理请求一致的供应商鉴权头。
- 模型目录请求不再携带 `thinkingDepth`。

### 解析

只接受 `data` 数组中满足以下条件的 ID：

- 类型为字符串。
- `trim` 后非空。
- 长度不超过模型字段上限。
- 去重后保留稳定顺序。

模型数量设置硬上限。响应包含标准分页游标时继续读取后续页面，同时设置最大页数，防止无限分页或恶意上游消耗资源。

### 失败

模型目录失败返回明确错误，不再返回内置模型列表：

- `AUTH_FAILED`
- `MODEL_CATALOG_NOT_FOUND`
- `RATE_LIMITED`
- `UPSTREAM_TIMEOUT`
- `UPSTREAM_UNAVAILABLE`
- `INVALID_RESPONSE`

客户端保留当前模型文本和手动输入模式，显示失败原因与下一步建议。目录失败不阻断保存和连接测试。

## 思考深度

共享契约改为：

- `off`
- `low`
- `medium`
- `high`
- `max`

### OpenAI 兼容协议

- `off` 不发送 `reasoning_effort`。
- 其余等级原样发送 `low / medium / high / max`。
- 上游因不支持该字段或等级返回参数错误时，连接测试报告明确的不兼容错误。
- 真实对局不静默重试较低等级，避免配置展示与实际行为不一致；调用失败后沿用规则策略回落。

### Anthropic 协议

- `off` 不发送 `thinking`。
- `low` 映射为 1024 tokens。
- `medium` 映射为 2048 tokens。
- `high` 映射为 4096 tokens。
- `max` 映射为 8192 tokens。
- `max_tokens` 保持大于 thinking budget，并预留现有回答空间。

### 兼容迁移

- 服务端读取数据库、环境变量和预设时将旧 `8192` 规范化为 `max`。
- 服务端对外只返回 `max`。
- 客户端不再产生新的 `8192` 值。
- 非法思考深度不通过类型断言进入运行时；环境变量非法时启动失败并给出配置错误。

## 数据流

### 保存与启用

1. 客户端提交 provider、Base URL、API Key、模型 ID、思考深度和超时。
2. 服务端执行统一字段校验和旧值迁移。
3. 设置事务成功后重建运行期 LLM 客户端。
4. 后续 AI 决策读取新客户端并通过统一适配层调用上游。

### 获取模型

1. 客户端提交 provider、Base URL 和可选 API Key。
2. 服务端仅在 provider 与规范化 Base URL 一致时复用已保存密钥。
3. 安全上游层验证目标地址并发出目录请求。
4. 协议适配层解析真实模型 ID 和分页信息。
5. 服务端返回真实 ID 或结构化失败，不返回建议列表。

### 连接测试

1. 客户端提交当前未保存配置。
2. 服务端执行与保存相同的字段校验。
3. 统一适配层构造最小推理请求。
4. 安全上游层发出请求并限制响应。
5. 成功只返回 provider、model、耗时和密钥来源，不返回模型正文。

## 错误处理

- 无效 URL、provider、模型 ID、思考深度或超时返回 `INVALID_CONFIG`。
- 401 和 403 返回 `AUTH_FAILED`。
- 推理端点中的模型不存在返回 `MODEL_NOT_FOUND`。
- 模型目录端点不存在返回 `MODEL_CATALOG_NOT_FOUND`。
- 429 返回 `RATE_LIMITED`。
- 超时返回 `UPSTREAM_TIMEOUT`。
- 网络失败返回 `UPSTREAM_UNAVAILABLE`。
- 非法 JSON、超大响应或协议结构不符返回 `INVALID_RESPONSE`。
- 不向客户端返回上游正文、堆栈、API Key 或内部网络信息。

## 客户端行为

- 模型目录成功时展示真实模型数和可搜索 ID 列表。
- 模型目录失败时展示具体错误，不用成功 Toast 展示建议列表。
- 手动输入始终可用，当前手工值不会因目录刷新失败而清空。
- 思考深度下拉新增“最大深度 Max”；Anthropic 辅助文本显示 8192-token budget，OpenAI 辅助文本显示原生 `reasoning_effort=max`。
- 连接诊断指纹继续包含思考深度，切换到 `max` 后旧结果标记为过期。

## 测试策略

### 共享契约

- 五档思考深度类型与选项。
- 旧 `8192` 到 `max` 的规范化。

### 服务端设置

- 保存、读取、预设和环境变量中的 `max`。
- 旧数据库值兼容。
- 非法环境变量启动失败。
- 私网上游默认拒绝和显式允许。

### 协议适配器

- 两种协议的端点拼接、鉴权头和文本解析。
- 五档思考深度请求体。
- OpenAI `max` 原样传递。
- Anthropic `max` 映射为 8192。
- 上游不支持 `max` 时的错误分类。

### 模型目录

- OpenAI 与 Anthropic 的真实模型 ID。
- 空白、非字符串、重复和过长 ID 过滤。
- 空目录、非法结构、超大响应、超时、鉴权失败、限流和端点不存在。
- 标准分页、页数上限和模型数量上限。
- 失败响应不包含 fallback 模型。

### 真实对局客户端

- 成功返回合法候选动作。
- 两种协议与五档思考深度。
- 不跟随重定向泄露鉴权。
- 超时、超大响应、非法 JSON、空正文和非法候选 ID 返回 `null`。
- LLM 失败后规则策略继续完成决策。

### 客户端

- 模型目录请求不携带思考深度。
- 真实目录与失败响应状态处理。
- 手动模型输入在目录失败后保留。
- `max` 参与诊断指纹和预设序列化。

## 验收

- 使用受控 OpenAI 兼容测试服务完成模型目录、连接测试和真实决策闭环。
- 使用受控 Anthropic 协议测试服务完成相同闭环。
- 使用本机或局域网模拟端点验证“默认阻止、显式允许后可用”。
- 执行共享、服务端和客户端相关测试。
- 执行至少一轮设置页面浏览器冒烟测试和一轮 AI 玩家对局冒烟测试。
- 验证模型目录失败时不展示伪造的远程模型 ID。
- 验证 `max` 在请求体中的实际映射与界面说明一致。

## 变更边界

当前工作区已有大量未提交修改。实施只触碰第三方 LLM 设置、协议适配、安全上游、模型目录和相关测试文件，不清理、不覆盖其他现有改动。实施前创建独立分支以保留回滚点，但除非用户明确要求，不创建 Git 提交。
