## 审计确认（步骤 1）

1. **smoke 不调用真实 LLM**：
   - `e2e/helpers/wsClient.ts` 的 `WsClient.connect()` 在收到 welcome 后断言 `llmAvailable !== true`（否则抛 `E2E 服务端意外启用了 LLM`）。3 次运行均通过 → welcome 中 `llmAvailable` 为 `false`。
   - `playwright.config.ts` webServer `env` 只配 `PORT`/`DATA_DIR`/`LOG_LEVEL`，不含任何 LLM 变量。服务端 `llmProvider.isAvailable()` 依赖 `isLlmEnabled(config)`（需 apiKey，`core/game/llmProvider.ts:36`、`llmClient.ts`）→ 恒为 `false`，机器人走规则模式。
   - 独立探测：以完全相同的 env（仅 PORT/DATA_DIR/LOG_LEVEL）启动服务端直连 WS，welcome payload 实测 `{"protocolVersion":1,"connectionId":"c_…","serverVersion":"0.1.0-m1","llmAvailable":false}`。
2. **使用临时 DATA_DIR**：`start-server.mjs` 每次运行前 `rmSync` 清空 `e2e/.tmp-data`，再以该目录为 `DATA_DIR` 启动真实服务端（`node packages/server/src/index.ts`）；`serverEnv.ts` 的 `DATA_DIR = e2e/.tmp-data`、`DB_PATH = e2e/.tmp-data/platform.db`。每次运行全新数据库。
3. **/health/live 就绪探针**：`packages/server/src/gateway/http.ts:243` 存在 `url === '/health/live'` → 200 `{status:'ok'}`；webServer `url` 用 `${BASE_URL}/health/live`。
4. **真实 Chromium**：Playwright 1.62.1 + Chromium **151.0.7922.34**（`chromium.launch().version()` 实测）。smoke 经 `browser.newContext()` + 真实页面加载、DOM 断言渲染（非 API/mock）。与 `packages/server/tests/gatewayGame.test.ts` 成熟模式一致：seedRoom 直插 → 真实 WS resume/ready/start_game → 真实浏览器加入断言。
