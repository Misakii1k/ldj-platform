# D2 低风险原语实施结果

## 范围

本轮累计交付：

- 确定性随机加固。
- 座位与回合轮转原语。
- 《谁是卧底》和 UNO 对轮转原语的兼容迁移。
- 基础牌区原语加固，以及 UNO 对牌区原语的实验迁移。
- 白名单可见性策略组合，以及 UNO 与《谁是卧底》两款真实消费者的兼容迁移。

本轮没有修改 `GameModule` 契约、数据库 schema、服务端执行链、目录准入、UI 或任何 ruleset 语义，也没有实现 UNO 新平台规则、白板模式、异步裁判或新游戏。UNO 仍持久化原有 `deck`、`discardPile` 和 `hands`；共享牌区只在 reducer 内作为临时适配视图。

D1 人工批准仅允许内部 D2 重构。`undercover`、`landlord`、`werewolf` 继续为 `internal_prototype`，`uno` 继续为 `blocked_rights`；本包不构成任何权利、规则或发布批准。

## TDD 记录

### 确定性随机

新增 `packages/shared/tests/random.test.ts`。首轮测试中，历史序列与洗牌结果的手写期望值有两处不准确，先按当前实现真实输出修正；之后唯一红灯准确指向 cursor 未校验。实现非负安全整数校验后，6/6 目标测试与两份 D1 黄金回放通过。

代码复核随后发现：如果对极大但合法的 cursor 逐次快进，会造成进程长时间阻塞。补充失败测试并修复为基于 Mulberry32 32 位状态周期的常量时间恢复，同时增加：

- 大 cursor 与其 32 位周期等价位置产生相同后续随机值。
- cursor 达到 `Number.MAX_SAFE_INTEGER` 后拒绝继续抽取，不发生不安全整数递增。
- `nextInt` 只接受安全整数边界和安全整数宽度。
- 非法边界不消耗随机。

所有合法既有 cursor 的序列保持不变，两份 D1 fixture 未改写。

### 座位与回合轮转

新增 `packages/shared/tests/rules.turns.test.ts` 后，首次执行因 `turns.ts` 不存在而以 `ERR_MODULE_NOT_FOUND` 失败。实现最小纯函数 API 后，7/7 原语测试通过，覆盖：

- 顺时针与逆时针环绕。
- 多步跳过。
- 排除不合格参与者。
- 当前参与者已不合格时继续寻找。
- 从指定合格参与者旋转固定顺序。
- 输入不可变。
- 空顺序、重复参与者、未知参与者、无合格参与者、非法方向和非法步数。

原语不读取游戏状态，不包含游戏 ID 分支，不处理 UNO 双人反转或《谁是卧底》流程与胜负。

### 真实消费者迁移

1. 《谁是卧底》用 `nextTurnParticipant` 和 `rotateTurnOrder` 替换本地环序逻辑。目标模块测试、原语测试及 `undercover_classic_v1` 完整局黄金回放共 27/27 通过。
2. UNO 用 `nextTurnParticipant` 替换本地 `nextPlayer`。双人反转仍由 UNO 模块传入两步，不进入共用原语。两款游戏与原语目标测试共 39/39 通过。
3. 代码复核发现 UNO 初始化未拒绝重复玩家 ID；新增测试并在洗牌前拒绝重复 ID，避免无效顺序进入轮转原语且保证失败不消耗随机。这是原语前置状态不变量加固，不改变任何有效对局规则语义。复核还补齐了 `rotateTurnOrder` 对“无人合格”的明确错误路径。第一包最终目标测试为 40/40 通过。

### 基础牌区

先在旧 UNO 实现上增加 4 组重构特征场景，锁定普通摸牌、罚摸跨回收边界、只剩弃牌顶牌时摸零张，以及出牌移动的现有行为；10/10 UNO 模块测试通过。随后重写 shared 牌区测试，首次执行因缺少 `dealCards` 导出而在模块装载阶段失败，形成预期红灯。

实现后的 shared 牌区原语共 15/15 通过，覆盖：

- 只依赖实例 `id`，保留不含 `definitionId` 的游戏牌对象及全部自定义字段。
- 牌区存在、源/目标不同、数量与请求合法、全牌区实例 ID 唯一。
- 摸牌从源区头部取牌，按请求顺序移区并追加到目标尾部。
- 按有序目标逐轮发牌；失败时原子返回，不产生部分状态。
- 摸牌堆为空时保留弃牌区末尾顶牌，只洗回其余牌；两张弃牌时回收一张且不消耗随机。
- 所有拒绝路径不修改输入、不消费随机；洗牌输入与调用方数组隔离。

UNO 使用临时牌区 adapter 迁移了初始牌堆洗牌、每人 7 张轮流发牌、首弃牌实例移动、运行期逐张摸牌/回收和手牌到弃牌区移动。UNO 本地继续负责冻结 ID、首张数字牌规则、部分摸牌、出牌合法性、颜色、罚牌链、轮转及胜负。adapter 包含全部玩家手牌，shared 操作会验证整局实例 ID 唯一，但 `zones` 不写入状态、事件或视角。

迁移后 shared、UNO 模块与 UNO 黄金回放目标选择为 26/26；扩大到 random、turns、两款模块/黄金回放和完整 recovery 文件后为 73/73。完整 UNO D1 fixture 深比较通过，现有文件 SQLite 两次运行期回收测试继续精确验证状态、牌序、事件和非初始 cursor。

### 白名单可见性

共享 `visibility` 保留原有五种单一策略，并新增 `canObserveAll` 作为纯合取组合。它只判断接收者、owner 和 reveal 条件，不接收完整权威状态，不反射遍历字段，不包含游戏 ID 分支，也不决定淘汰、终局或胜负。

UNO 继续显式构造原有公开字段和键顺序，只用 owner-only 判断本人 `me`：本局玩家看到自己的手牌与合法牌 ID，未知玩家仍得到 `me: null`，观战视角仍完全省略 `me`。完整 deck、其他玩家 hands 和牌区 adapter 字段从未进入候选视角。

《谁是卧底》保留公共、本人和观战三层显式白名单：每名玩家的 `revealedRole` 使用该实体已淘汰或全局终局的 reveal 条件；本人 `role` 同时满足 owner-only 与 reveal；双词和完整角色表只在终局进入顶层 `reveal`。完整逐票、另一阵营词、未公开角色与 `pendingOutcome` 从未进入候选视角。

兼容测试额外锁定：

- 玩家、未知玩家和观战三种 `me` 形状。
- 顶层、玩家摘要和本人对象的键顺序。
- 隐藏字段的显式 `null` 与省略差异。
- 视角构造不修改权威状态。
- 两份完整局黄金回放的逐步玩家/观战视角深比较。
- 真实 WebSocket 玩家定向秘密和观战隐私。
- BotRunner 继续只消费普通玩家视角。

文件 SQLite 恢复测试新增逐玩家与观战 `JSON.stringify` 等价断言：《谁是卧底》覆盖部分确认的 word-reveal 和已投两票的 voting 中间状态；UNO 覆盖末席已摸牌状态。恢复前后的秘密、公共进度、字段形状和键顺序完全一致，同时保留原有 snapshot、RNG、事件与计时器断言。

第四包目标选择共 68/68 通过。两份冻结 fixture 未改写，摘要保持不变。

## 恢复边界验证

第二实施包只增强 `packages/server/tests/recovery.test.ts`，没有修改生产恢复链、数据库 schema、游戏规则、目录准入或 UI。测试使用现有 `seedRoom` 历史夹具建立临时文件数据库，后续开局、动作、持久化和启动恢复均经过真实 executor、session 与 `runStartupRecovery` 链。

新增或强化的恢复证据：

1. 《谁是卧底》首轮 reveal 超时：从持久化非零 cursor 计算预期首位，重启后精确验证 `roundFirstSpeaker`、完整 `speakingOrder`、cursor/seq 增量、系统动作事件以及 reveal/speech 计时器。
2. 《谁是卧底》下一轮结果超时：使用独立席位数组算法计算下一名存活首位和完整顺序，重启后精确验证第二轮轮序、cursor 不变、seq 增量、持久化事件和计时器。
3. UNO 末席已摸牌状态：重启前后 snapshot 与 RNG JSON 字节一致，重启后过牌准确环绕首席、cursor 不变，并核对持久化玩家动作事件。
4. UNO 运行期回收：第一次真实弃牌回收把 cursor 推进到非初始值；第二次回收跨重启后与不中断 oracle 的抽牌、完整 deck 顺序、状态、事件和 cursor 完全一致。测试独立断言洗牌 cursor 增量，并在边界、抽牌后和过牌后验证总计 108 张、实例 ID 唯一、弃牌顶牌保持。

恢复测试共 14/14 通过；D2 相关目标选择共 54/54 通过。恢复包没有新增生产测试后门，也没有改写任何 D1 fixture。

仍保留以下边界：gateway 重连和 TimerRunner 重挂属于后续平台级恢复验收；malformed `rng_state_json` 的启动恢复策略尚未由规范裁定，本包没有擅自修改平台错误处理。

## 成熟度结论

- `random`：**实验**。已经具备确定性、续接、不可变洗牌、游标边界、常量时间大游标恢复，以及真实文件数据库中由运行期洗牌产生的非初始 cursor 续接证据。由于 malformed `rng_state_json` 的启动恢复策略和更广故障矩阵尚未裁定，本包不将其晋升候选。
- `turns`：**候选**。已由《谁是卧底》和 UNO 两款结构不同的游戏真实复用，通过两份完整局黄金回放，不包含游戏 ID 分支，并覆盖空集合、重复顺序、非法参与者、不可变性及两款消费者的文件数据库恢复边界。它仍未通过第三游戏验证和稳定原语的完整恢复/视角门，因此不得称为稳定。
- `cards`：**实验**。已由 UNO 真实复用初始洗牌/发牌、首弃牌移动、运行期摸牌/回收和出牌移动；通过 shared 边界、UNO 模块、完整局黄金回放、不可变性、视角结构与文件 SQLite 非初始 cursor 回收证据。它只有一款真实消费者，错误/API 仍可调整，未通过第二款结构不同游戏和第三游戏验证，因此不得称为候选或稳定。
- `visibility`：**候选**。UNO 与《谁是卧底》两款结构不同的游戏已真实复用无游戏 ID 分支的策略判断；完整局黄金回放、玩家/观战白名单、运行时键序、真实 WebSocket、机器人消费路径与文件 SQLite 恢复前后视角 JSON 等价均通过。它仍未经过第三款验证游戏与稳定原语的完整契约门，因此不得称为稳定。
- `ballot`、`flow`、`scoring`、`buzzer`、`hosted`、setup UI 和 tabletop UI：不属于本包验收，不因已有文件或导出获得成熟度提升。

因此，**D2 获批的随机、轮转、基础牌区与白名单可见性四项范围已经完成**。这不表示共享引擎总计划完成：`random`、`cards` 仍为实验，`turns`、`visibility` 仍为候选，没有原语稳定；D3 迁移批准、统一视角/桌面、开发工具链、第三游戏验证和七款新游戏均未开始或未获批准。下一步必须先申请并规划 D3 迁移与兼容门，不得直接进入 D4 或新游戏发布开发。
