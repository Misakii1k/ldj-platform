# D4-UI0 统一桌面基础结果

## 范围

为统一桌面奠定基础，不改任何游戏主舞台：断线/服务恢复期间保留已渲染内容（不整页替换）、动作忙碌状态按 `(action, object)` 隔离、非模态连接状态横幅、组件归属样式（CSS Module）。本门先调用 `oil-frontend` 评审既有落点后实施。

## 交付物

### 连接资源状态

- `packages/client/src/connection/types.ts`：`ConnectionSnapshot` 新增纯派生标志 `isRefreshing`（`connState === 'reconnecting'`）与 `isRecovering`（`connState === 'server_recovering'`）；`derivedFlags(connState)` 与 `withConnState` 保证状态机每次迁移都同步标志。
- `packages/client/src/connection/envelopeReducer.ts` / `ConnectionContext.tsx`：所有 connState 迁移（welcome、STALE_CLIENT_STATE、resync_required、room_snapshot、socket.onclose、手动 resync）统一经 `withConnState`，避免标志过期。

### 路由器保留内容

- `packages/client/src/App.tsx`：`reconnecting` / `server_recovering` 且已有 `room` 或 `game` 内容时，保留当前渲染视图（RoomPage / GamePage / 同步加载 / 关闭页）并在顶部叠加 `<TabletopStatusBanner />`；无内容时维持原全屏 loader。其余路由不变。

### 动作忙碌范围

- `packages/client/src/game/actionState.ts`（纯 reducer，无 React）：`ActionKey { action, object }`、`actionKeyString`（JSON 注入安全）、`beginAction/failAction/settleAction/isBusy`；按键隔离、不可变、未知键安全。
- `packages/client/src/game/useScopedAction.ts`：`{ state, act(key, payload), errorFor(key) }`，错误持续到下一次 begin。
- `packages/client/src/game/useGameAction.ts`：委托给 scoped 机制（默认键 `game_action/table`），导出 API 与既有消费者（NewGamePages / WerewolfGamePage）完全兼容。

### 状态横幅与样式归属

- `packages/client/src/game/TabletopStatusBanner.tsx` + `TabletopStatusBanner.module.css`：非模态 `role="status"` / `aria-live="polite"`，恢复中提供「重新同步」；样式只存在于组件归属 CSS Module，未向全局 `styles.css` 追加。
- 新增 `packages/client/src/vite-env.d.ts` 声明 `*.module.css`（仓库此前无 CSS Module 环境声明，typecheck 必需的最小补充）。

## 测试

- `packages/client/tests/actionState.test.ts`（7 项）：actionKeyString 唯一性、begin 不可变、settle 不影响其他键、fail 只影响该键、错误持续到下次 begin、未知键安全、不同键互不覆盖。
