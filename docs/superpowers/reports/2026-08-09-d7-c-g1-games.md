两款游戏均已 playable 上架：首页可见、可建房、真实 WS 完整局到服务端正式战绩。全量 `npm run ci` 各门全绿（typecheck / lint / 880+68 测试 / D1 合规 / build / **18 条 E2E 全过**）。

## 一、共享层接线（C1，提交 d4350bb）

- `registry.ts` 注册 `durianModule`/`loveLetterModule`；`catalog.ts` 新增两款条目（botSupport `none`）；`tsconfig.server.json` 补 paths 别名。
- 准入台账新增两款记录（先 coming_soon，C4 转 playable）。
- 冻结断言同步：catalog / gameSession / playable-check / launch-playable 计数。
- 首页可见：两款卡片 + 禁用「即将推出」按钮（截图 `d7-shots/c1-home-coming-soon.png`）。

## 二、schemas 转 zod + 契约测试（C2，提交 a85907b）

- 两游戏 `parseConfig/parseAction/视图解析` 改为严格 zod（多余字段拒收，错误消息与既有断言一致），package.json 声明 zod。
- 新增每款 manifest / registry / views / contract 四套独立测试；游戏测试 41 → 56 项。

## 三、客户端页面（C3）

- 客户端严格 view parser：`game/durian/types.ts`、`game/loveletter/types.ts`。
- 页面首次接入共用桌面框架：`TabletopShell + PlayerStrip + ActionDock + GameDrawer`。
  - durian：订单双选项、需求/怒气面板、按铃窗口、他人库存（本人隐藏）、规则抽屉。
  - loveletter：手牌选择、目标选择（排除被庇护者，王子可选自己，无合法目标可无目标打出）、守卫猜身份、好感进度、查验记录（仅本人）。
- `viewRegistry.ts` + `GamePage.tsx` 懒加载接线。
- **修复既有模块缺陷**：平台开局投递的 `{ type: 'begin' }` 系统动作此前不在两游戏动作 schema/reducer 中，导致 `start_game` INTERNAL_ERROR；已按 werewolf v2 惯例补齐幂等 begin。

## 四、准入 playable + E2E（C4）

- `game-admission.json`：durian → `internal-admission-d7-2026-08-09-d01`（原创，同 landlord 模式）；loveletter → `internal-admission-d7-2026-08-09-l01`（按用户确认的授权证据记录，来源见 `docs/game-library/桌游平台游戏库资料/06_情书`）。
- 目录两款 `availability: playable`；`botSupport: none`（房间不提供添加机器人入口）。
- E2E（`--retries=0`，botSupport none 故全部真人驱动）：
  - `e2e/durian-tabletop.spec.ts`：2 人局 Node+浏览器交替接单/按铃/裁定至终局，隐私断言（本人库存隐藏、中央库存/权威库存不入视图），服务端战绩落库。通过（~3s）。
  - `e2e/loveletter-tabletop.spec.ts`：2 人局交替出牌至好感阈值终局（~13 轮），手牌隐私断言，服务端战绩落库。通过（~50s）。
  - 期间加固 E2E 驱动：wsClient 新增 `latestGameState`（取最新帧并清旧帧），host 驱动轮询最新权威状态 + 快照去重，消除满负荷下旧帧竞态。
