## 关键语义修复（不改实现仅为过绿，对齐真实契约）

1. **abort_game 是合法终局（不是"被错误视为 terminal"）**：平台契约以
   `resultCandidate !== null` 判定结束（`session.ts`：`finished = gameResult !== null`，
   `aborted = finished && gameResult.aborted === true`，ABORTED 不写战绩 FR-RESULT-002）。
   classic 的 `getResult` 对 abort 同样返回结果（`aborted:true`）。因此模块 `abort_game`
   产生 `resultCandidate { aborted:true, winner:null }` 是正确的；`buildBlankResult` 保持
   "非 game_over 返回 null"、模块 resultCandidate 仅终局。失败的
   `undercover_blank_counts_as_undercover_side_test` 期望值（null）与契约相悖，
   已按契约改为断言 aborted 结果 + ROLE-002 roles/blankWord 映射。
2. **外部裁判结果必须存在**：zod v3 把 `z.unknown()` 推断为可选键
   （`result?: unknown`），与 types.ts 的 `BlankAction`（`result: unknown`）不兼容；
   在模块边界 `parseAction` 显式收窄（与 effects 在模块边界 cast 一致的做法）。
3. **eligibility digest 修正**：终局猜词发生在白板被淘汰后，`alive` 记录改为真实
   `p.alive`（此前恒为 true）。

## 已知缺口 / 明确 blocker

1. **平台 startGame 仍按 gameId 取默认模块**（`session.ts` 不在白名单，未改）：
   `startGame` 先用 `requireModule(gameId)`（默认 classic）创建初始状态，再解析
   `rulesetId` 写入会话。`resolveRulesetForStart` 现可正确解析 blank ruleset，但会话
   `requireSessionModule` 之后会按 blank 模块解析——平台侧直接开局 blank 的完整链路
   需 session.ts 把模块解析改为 `getGameModule(gameId, rulesetId)`（后续独立窗口）。
   现状：blank 在目录为 `internal_prototype`（GOV-001 未验收不 playable），正常客户端
   无法经 catalog 新建对局，与冻结条款一致。
2. **ADJ-001 本地精确/主备模型链、ADJ-002 fallback 隔离与日志脱敏、NORM 核心策略、
   TASK-001 重启恢复/重放零 provider 调用、ASYNC runner 时序**为平台/shared 职责：
   shared `rules.adjudicationPolicy.test.ts` 与平台 adjudicationRunner/Task/recovery/boot
   （P3 主线程核验 62/62）已覆盖；模块侧只测其集成点（payload 三字段、verdict 应用、
   明文擦除、序号冻结），未在 blank 侧重复实现。
3. **server 端 blank 完整局矩阵（fullGameMatrix）未新增**：`fullGameDriver` 仅支持
   默认 ruleset；blank 走 registry 解析 + 模块级 57 项 + P3 平台链路覆盖。逐动作崩溃
   恢复矩阵留待 blank 独立验收（GOV-001 admission）窗口。
4. **NORM 项以模块集成断言为主**（归一化策略函数本体由 shared 测试覆盖），报告计数为
   模块路径上的真实断言，非重复实现。
5. **werewolf v2 既有 typecheck 错误（11 处）** 在范围外，未触碰。
