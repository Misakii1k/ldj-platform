# D4-F2 SUSPENDED 与类型化失败恢复结果

## 范围

规则模块内部错误（reduce 抛错、next state schema 失败、invariant 失败、未知 effect、不可序列化输出）进入 `SUSPENDED` 会话并携带类型化失败码；原动作事务回滚、零写入；平台在重启恢复时确定性恢复到 ACTIVE 并清除失败码；规则集不可用时以 `FAILED_RULESET_UNAVAILABLE` 异常终止且不写正常战绩。

## 交付物

### 共享失败语义

- `packages/shared/src/game/sessionStatus.ts`：
  - `SUSPENDED_REASON_CODES`（`SUSPENDED_REDUCE_FAULT` / `SUSPENDED_STATE_SCHEMA` / `SUSPENDED_INVARIANT` / `SUSPENDED_UNKNOWN_EFFECT` / `SUSPENDED_UNSERIALIZABLE`）。
  - `FAILURE_CODES`（`FAILED_RECOVERY` / `FAILED_INVARIANT` / `FAILED_RULESET_UNAVAILABLE`）。
  - `GameInternalError`（与用户输入拒绝 `CommandError` 严格区分）。
  - `sanitizeFailureDetails`：只保存有界元数据（module/ruleset/session/seq + 200 字符 message），绝不保存快照正文、手牌、角色、猜词、密钥或堆栈。

### 会话执行链

- `packages/server/src/core/game/session.ts`：
  - `applySessionAction` 增加可选已解析模块参数；动作内部区段包裹 try/catch：`CommandError`（用户拒绝）直接抛出、不暂停；其余内部故障 → `writeSuspended` 单独事务写 `SUSPENDED + failure + failure_details_json`，对外抛出稳定的 `INTERNAL_ERROR`（不泄露内部细节）。
  - `writeSuspended` 不取消 pending 计时器：SUSPENDED 期间计时器不触发，重启后按既有 RECOVERING 流程重挂，保证可确定性续跑。
  - effects 循环新增 `default` 分支：未知 effect 类型 → `SUSPENDED_UNKNOWN_EFFECT` 失败关闭（此前静默跳过）。

### 恢复

- `packages/server/src/core/recovery.ts`：
  - 步骤 2 活动会话查询加入 `SUSPENDED`（此前 SUSPENDED 会话完全绕过恢复）。
  - `abortSession` 接受类型化失败码并写入 `failure` 列；`failureCodeForReason` 映射：`REASON_RULESET_UNAVAILABLE → FAILED_RULESET_UNAVAILABLE`、schema/corrupt → `FAILED_RECOVERY`。
  - 步骤 5 转 ACTIVE 时清除成功恢复会话的 `failure` / `failure_details_json`。
- `packages/server/src/core/game/views.ts`：SUSPENDED 会话下发 `game_state`（status='SUSPENDED'），供客户端暂停/等待层展示；RECOVERING 仍不下发。

## 测试（`packages/server/tests/suspended.test.ts`，6 项）

1. reducer 内部故障 → 会话 SUSPENDED、`SUSPENDED_REDUCE_FAULT`、last_seq/快照/事件零变化、外部收到 `INTERNAL_ERROR`。
2. nextState schema 故障 → `SUSPENDED_STATE_SCHEMA`。
3. 未知 effect → `SUSPENDED_UNKNOWN_EFFECT`。
4. 用户输入拒绝（`CommandError`）不暂停会话、不写 failure。
5. 重启恢复：SUSPENDED → 确定性恢复 ACTIVE 并清除失败码（文件 SQLite 关闭→重开→启动恢复）。
6. 规则集不可用 → ABORTED + `FAILED_RULESET_UNAVAILABLE`，不写 `game_results`。
