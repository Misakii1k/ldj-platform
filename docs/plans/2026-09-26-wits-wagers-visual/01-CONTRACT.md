## 1. 设计方向

- **一句话**：打烊后的赌场贵宾厅——一盏绿罩吊灯压在椭圆毡桌上；答案是象牙色扑克牌，下注是真筹码，玩家左右围桌而坐。
- **表皮**：深色悬疑（`DESIGN-DIRECTION.md` C12）→ 1–1.5px 黄铜 / 暗色细边 + 贴纸阴影，**不用粗墨边**（C2）。金色只做描边、大字和赔率牌；**黄色只给每个视口唯一的主按钮**。
- **档位**：平面舞台 + 场景纵深（吊灯光锥、椭圆桌透视用径向渐变表现）。**不引入** `.stage-felt-3d` 的 rotateX 倾斜：方向稿是正视毡面。
- **对标**：项目内狼人杀（左右席位 C10）；项目外 Balatro 只取筹码手感与计分演出（C13），不取霓虹色和像素风。

## 2. 状态模型（驱动画面的字段）

全部来自现有 `WitsWagersPlayerView`（`types.ts`），**不新增服务端字段**。可见性以 `packages/games/wits-wagers/server/views.ts` 为准（C18）：

| 字段 | 画面变化 |
|---|---|
| `phase` | 四个画面切换：`answering` → ①；`arranging` → ②；`betting` → ③；`settlement` / `game_over` → ④ |
| `round` / `totalRounds` | 顶栏「第 N / 7 轮」，N 用衬线金色大字 |
| `deadlineAt`（answering / betting 有值） | 顶栏右侧倒计时环；`arranging` 显示「…」满环；`settlement` 不显示 |
| `question.prompt` / `.unit` | 题目衬线大字 + 「单位：X」；`settlement` 缩成一行灰字 |
| `players[].hasSubmitted` | ① 席位卡状态灯：已交牌（绿灯）/ 思考中（灰灯 + 闪烁省略号）；背面牌堆张数 |
| `players[].score` | ②③ 席位卡余额（衬线大字）；④ 起点值 |
| `players[].forfeited` | 席位卡整体 45% 透明 + 「已退席」代替状态行（方向稿没画，见待确认 Q3） |
| `board[]`（arranging 起公开） | 扑克牌一排：`value`、`odds`、`authors`（牌右上角作者色点）；`lower` 格是虚线透明牌「更低 · 比所有牌都小」 |
| `publicBets`（betting 起公开） | 各格底部筹码摞；③ 里**我的**筹码不画在桌上，由托盘飞上去 |
| `me.acceptedBets` / 本地 `betDraft` | ③ 托盘两枚筹码 A/B、目标牌面值与赔率、`+N` 加注步进 |
| `me.available` / `me.reserved` | ③ 托盘「可用 N / 余额 M」 |
| `revealed.question.answer` / `.sourceNote` | ④ 黄铜牌匾里的答案数字 + 来源小字 |
| `revealed.winningTargetIds` | ④ 胜出牌升起 + 扫光 +「最接近」绶带；其余牌压暗。**等距双胜两张都高亮**（方向稿只画了单胜，见 Q4） |
| `revealed.ledger[]` | ④ 席位卡：`scoreBefore → scoreAfter` 计数、增减徽章（`winProfit - loss + authorBonus`）、`authorBonus > 0` 时「作者 +3」 |
| `result`（game_over） | 总排名画面**保持现状**（用户 2026-09-27「总排名画面先保持现状」）：`ResultPanel` 的 game_over 分支不改布局，只把金额换成「分」、颜色换成本契约令牌 |

**金额单位**（用户 2026-09-27「改成筹码，显示分」）：界面上所有余额、增减、加注都写「N 分」或筹码上的「+N」，**不再出现 ¥ 和钞票**。服务端 `score` 本来就是分，前端不做换算。

隐私（任何任务都不许破）：`answering` 阶段 DOM 里不得出现任何人的估数（包括自己的估数以外的数字）；`arranging` 不得出现下注；这些本来就由服务端保证，前端**不要从别处拼**。

## 4. 关键画面

构图共同点（两个视口都成立）：
- 背景：房间暗墙 + 顶部居中吊灯（绿罩 + 黄铜下沿）+ 向下的暖色光锥 + 椭圆毡桌（木沿 + 黄铜细圈）。桌面下沿印「一 智 千 金 · 贵 宾 厅」（仅桌面）。这些是 `.stage-art` 性质的装饰层，`pointer-events: none`。
- 顶栏：左「第 N / 7 轮」、中阶段胶囊（作答 / 排牌 / 下注 / 揭晓）、右倒计时环。
- 席位：**桌面** 左 3 右 3，贴着椭圆桌两侧，不压在牌上；**手机** 题目下方 3×2 网格（用户最终选定，不是左右两列）。
- 每个视口只有一个黄色主按钮，贴底部居中（手机全宽）。

### 4.1 席位卡（所有画面共用）

桌面 184px 宽：左侧 52px **筹码形座位章**（玩家色 + 边缘白色镶片 + 中心象牙嵌片 + 座位号衬线字）；右侧上行名字 17px 粗体（自己加小金色「你」标签），下行状态区。
手机：座位章 30px，名字 13px，「你」标签隐藏，余额 17px 不带「分」字。
长昵称单行省略号截断，**卡片不许被撑高或撑宽**。

| 画面 | 状态区 |
|---|---|
| ① 作答 | 灯 + 「已交牌」（绿灯带光晕）或「思考中…」（灰灯，省略号闪烁） |
| ②③ | 衬线 26px 余额 +「分」 |
| ④ 结算 | 余额从 `scoreBefore` 计数到 `scoreAfter`，旁边增减徽章（加分绿底、扣分红底、持平灰底）；有作者奖时卡右上角「作者 +3」金色小签；左上角名次圆章；第 1 名整卡黄铜高光 + 名次章上方金色 ♛ |

自己的卡始终有 1.5px 黄铜描边 + 柔光。

### 4.2 ① 作答（answering）

- 中央：题目 40px 衬线（手机 24px），上方小字「写下你的估数」，下方「单位：米」。
- 题目下：**背面牌扇形堆**，张数 = 已交人数；每张酒红菱格牌背 + 象牙白边 + 中央黄铜「智」字圆章。牌堆下「N / 6 已交」。
- 再下：输入框（黄铜细边，44px 衬线数字 + 闪烁光标 + 单位），提示「写一个正整数；估得越接近、又不超过越好」。
- 主按钮：「交出答案」。已交后按钮变为次要样式「已交 · 可修改」或按现有 `GuessPanel` 逻辑（**不改提交逻辑**）。

### 4.3 ② 排牌（arranging）

- 题目同 ①。
- 中央一排格子（桌面横排；手机 3 列网格）：每格 = 顶部**黄铜赔率牌**「净赢 ×N」+ 下方**象牙扑克牌**（94×132，手机 78×92）。牌面：中央衬线数字 + 下方单位；左上 / 右下（旋转 180°）牌角索引「数字 + 红 ♠」；右上作者色点；淡 ♠ 水印；纸纹；金色内框。
- 第一格固定是「更低」：透明虚线牌，写「更低 / 比所有牌都小」，赔率 ×6。
- 底部无按钮，改为黄铜色文字「排牌中，马上开始下注…」。

### 4.4 ③ 下注（betting）

- 牌同 ②，每格底部出现**筹码摞**：所有人（除自己外）押在该格的筹码，后一枚压住前一枚 18px（手机 15px）；有加注的筹码底部挂金色「+N」小签。
- 底部托盘（主按钮上方）：「可用 **N** / 余额 M」（衬线 30px 金色）| 筹码 A（46px）+ 目标「324 ×3」+ 步进器「− +4 +」| 筹码 B 同结构。
- 交互沿用现有 `BetEditor` / `betDraft`（选中筹码 → 点牌放置 → 步进加注 → 保存）。**只换皮，不改规则**。
- 主按钮：「确认下注」。

### 4.5 ④ 揭晓结算（settlement）

- 题目缩成一行 20px 灰字，放顶部。
- 其下**黄铜牌匾**：小字「正确答案」+ 72px 衬线金色数字（手机 48px）+ 单位 + 来源小字。
- 牌与筹码同 ③；胜出格加「最接近」绶带、牌升起放大 1.12、斜向扫光循环；其余格压暗到 34% + 去饱和。
- **没有单独的排名表**：分数直接落在左右席位卡上（见 4.1 结算行）。这一条是 A2 相对 A 的结构变化，见 Q6。
- 主按钮：「下一轮」（沿用现有 `ResultPanel` 的推进逻辑；最后一轮进 game_over，game_over 画面保持现状）。

## 5. 动效与音效

### 5.1 动效硬约束（2026-09-26 用户反馈「经常会跳画面、抖动，或者突然一下子移动」后查明，全部必须遵守）

1. **弹跳 / 缩放 / 位移动画用独立 CSS 属性 `scale` / `translate`**，不许用 `transform` 做关键帧——`transform` 会把元素原本用来定位或居中的 `translateX(-50%)` 覆盖掉，整块横跳。确实要动 `transform` 的元素，本身不能靠 `transform` 定位。
2. **演出没有开场延迟**：新阶段的 DOM 渲染出来的同一帧就挂上动画起始帧（Web Animations `fill: 'backwards'` / `'both'`），不许先显示终态再倒回起点。
3. **动画结束后不许把元素重置成透明 / 旧位置**：用 `fill: 'both'` 或结束后写终态样式，不要在动画开始前手动 `style.opacity = 0` 而结束时又没有复原。
4. **物件插进一摞（筹码、背面牌）时用 FLIP**：插入前量出已有物件位置，插入后让它们从旧位置滑到新位置（260ms），不许瞬移。
5. **切阶段 / 组件卸载时取消上一段演出**：取消进行中的动画、清掉飞行物，旧演出链不许再改新画面（飞行物从左上角横穿、数字被改回旧值都是这个原因）。现有 `useWitsWagersStage` 已按 `round:phaseEpoch` 去重，新演出沿用这套机制。
6. **滚动计数的数字**用 `font-variant-numeric: tabular-nums` + `min-width`（答案 `3ch` 起，按位数算；分数 `2ch`），位数变化时所在容器不许变宽。
7. **不做屏震**：A2 已去掉全部屏震（`DESIGN-DIRECTION.md` §5 原本允许 ≤4px）。打击感由胜出牌升起、扫光和数字弹跳承担。要不要加回来，见 Q7。
8. 飞行物必须挂在带 3D / transform 祖先的外壳**之外**（现有 `WitsFlightLayer` 注释已写明原因），落点坐标用屏幕坐标实测。

### 5.2 四档行为

| 时刻 | `default` | `reduced` | `minimal` / `off` |
|---|---|---|---|
| ① 背面牌落桌 | 从上方 60px、-12° 旋入，依次间隔 120ms，420ms 回弹 | 只淡入，间隔 60ms | 直接显示 |

| ② 牌上桌 | 「更低」先淡入；其余牌依次从上方 50px + 绕 Y 轴 90° 翻入并回弹，间隔 160ms、每张 480ms；全部到位后赔率牌依次弹出（scale 0 → 1.3 → 1） | 依次淡入，间隔 80ms；赔率牌直接出现 | 全部直接出现 |
| ③ 下注 | 托盘筹码沿 120px 高抛物线飞到目标格、旋转 360°，落地 scale 1.4 → 1 回弹，已有筹码 FLIP 让位；托盘里原位变 25% 透明 | 淡出 / 淡入到位 | 直接出现 |

| ④ 筹码回收 | 所有筹码飞回主人的座位章：押中的高抛（150px、640ms、转 540°），押错的低掠（30px、460ms），逐枚间隔 70ms | 淡出 | 直接消失 |

| 倒计时 | 平台 `.stage-countdown` 行为（≤10 秒变色，≤5 秒滴答 + 脉冲） | 同平台降级 | 同平台降级 |

音效：沿用现有 `stage/audioCues.ts` 的 cue，按上表时刻触发（交牌、翻牌、下注落地、胜出、计分）。**不新增音频文件。**
