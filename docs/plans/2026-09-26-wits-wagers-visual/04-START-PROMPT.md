# 04 · 交给执行模型的提示词

## 首次开工（复制这一段）

你接手 D:/项目 的一智千金「深夜赌场贵宾厅」视觉改造。方向已由用户选定，你只负责照做，**不做任何新的视觉决定**。

先只读这几个文件：
1. D:/项目/docs/plans/2026-09-26-wits-wagers-visual/README.md
2. D:/项目/docs/plans/2026-09-26-wits-wagers-visual/PROGRESS.md（**先看「待用户确认」**：标「阻塞」的问题没答复，就跳过它所在的任务）
3. D:/项目/docs/plans/2026-09-26-wits-wagers-visual/02-TASKS.md 中第一个可做的 TODO 任务那一节

然后按该任务卡执行。视觉任务开工前，用浏览器打开 D:/项目/docs/ui-preview/wits-wagers/directions/A2-casino-lounge.html，切到卡片写的画面，点「▶ 播放演出」看节奏，它就是像素参照。尺寸、颜色、时长照方向稿和 01-CONTRACT.md 抄，不要自己发挥。

规则：
- 一轮只做一个任务；只改卡片白名单里的文件。
- 动效必须遵守 01-CONTRACT.md §5.1 的 8 条硬约束（用户反馈过「跳画面、抖动、突然移动」），做完用 scripts/check-stage-jitter.mjs 检测。
- 遇到方向稿没画、计划也没写的细节，停下，在 PROGRESS.md 的「待用户确认」写清问题，交回用户。
- 做完跑卡片要求的命令，把命令和退出码写进 PROGRESS.md；失败就修到通过，不许删断言、不许放宽隐私。
- 视觉好不好只由用户看图判定。你只能写「待用户看图」，不能写 PASS / 达标 / 已对齐。
- 回复不超过约 250 字：做了什么、命令结果、未通过项、下一个任务。

## 后续继续（短提示）

继续 D:/项目/docs/plans/2026-09-26-wits-wagers-visual/PROGRESS.md 中下一个可做的 TODO 任务（先看「待用户确认」有没有新答复）。只读 02-TASKS.md 对应一节、01-CONTRACT.md 被引用的小节和 A2 方向稿对应画面。遵守白名单，跑卡片命令和跳动检测，更新 PROGRESS。回复 ≤250 字。

## 独立复核（不改代码，可选）

只复核刚完成的任务 Xxx：读任务卡、本次 diff、命令日志、A2 方向稿对应画面。检查：是否超出白名单；`answering` 阶段 DOM 是否泄露他人估数；同一视口黄色按钮是否 >1；是否有新字面量色 / 非契约断点；是否用了 `transform` 关键帧做弹跳、是否有开场延迟、插入是否瞬移（跑 scripts/check-stage-jitter.mjs）；是否混入 C / B 稿元素；手机席位是否仍是顶部 3×2。输出 ≤5 条具体问题（文件 + 场景 + 影响），没有问题就说明核对了哪些。
