## 固定的工作方式

- 不重新设计产品，不改变游戏规则，不拿旧截图替换当前中央舞台与两翼席位。
- 低成本模式：一个小模型主执行，按任务串行推进；不是一次塞入整个项目，也不是同时启动很多模型。
- 可并行但非必要：T01 完成后，T02 私聊服务端与 T03 纯时间线可并行；T06 与 T07 会碰网关，禁止并行；T08/T09/T10 会碰舞台及主题，禁止并行。一个工作区中同一文件同一时间只有一个写入者。
- 上下文控制：每轮只读入口、当前状态、契约的相关章节和当前任务；不重新搜索整份历史。任务结束留下文件、命令、结果、失败原因和下一个任务。
- 不允许小模型降低验收要求、删除失败测试、使用 any/ts-ignore 吞掉协议问题、把隐私校验挪到浏览器，或靠 setTimeout 模拟服务端流程。
- 一次任务如果超过约 6 个生产文件或需要跨层改协议，先拆分为 .a/.b 子任务并写明依赖；确有必要的核心适配例外见任务卡。不要用一次大改掩盖断点。
- 修改公共 API 必须同步契约、类型、运行时解析、生产者、消费者和测试；不得让各端各猜一套字段。
- 遇到契约冲突，暂停该任务，在 04-PROGRESS.md 记录具体冲突和最小建议；不要自作主张换架构。用户可以只把冲突交给强模型短审，而非让强模型写全程。

## 完成的定义

代码已写 ≠ 类型通过 ≠ 单元通过 ≠ 浏览器通过 ≠ 真机/真实音频通过。
交付状态只能取 TODO / IN_PROGRESS / IMPLEMENTED / VERIFIED / BLOCKED。
IMPLEMENTED 不能写“全部完成”；只有所有要求的证据齐全才可标 VERIFIED。
