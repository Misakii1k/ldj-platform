## 2. 固定玩法主线（R01–R12）

> **2026-09-22 判定规则修订（平台适配 v1）**：实测中"离正确答案最近的估数却判负"被用户判定为反直觉。
> 经用户确认，R04/R06/R10 由官方的「最接近且不超过」改为「绝对差值最近」，
> 特殊槽由单个「全部猜高」拆成「更低」「更高」两个边缘槽，超时不再补答。
> 因此本版**不是**官方规则的逐条复刻，产品标签仍为"平台适配版"。

- R01：3–7个参赛席位，每席位独立余额0、永久筹码 A/B 各一枚，每枚基础下注值1；筹码本身不计最终分数。席位可以代表同机讨论的小队。
- R02：每局7个不重复问题，服务器主持和充当银行；题面给明单位，答案是可精确比较的数字。首版统一正整数单位，不让小模型自行解析“2万/约三成”。
- R03：秘密作答，截止后同时公开全部猜测。猜测按数字去重再升序，重复值保留全部作者名单。
- R04（2026-09-22 修订）：胜利值取 `argmin |guess - correctAnswer|`；精确命中即差值 0，自然独赢。
  答案高于全部估数则「更高」槽获胜，低于全部估数则「更低」槽获胜。
  两个估数与答案等距时**两者并列获胜**：各自按自己的赔率赔付，两边作者都拿作者奖。
- R05：赔率由**不同猜测数量**决定，不由玩家数决定。1或2个不同答案也必须正确支持。
- R06（2026-09-22 修订）：只能押含答案的槽或两个边缘槽「更低」「更高」。偶数答案时中心空位不能投注；其他空位也不能投注。
- R07：每枚永久筹码最多关联一个目标，两枚可同目标或不同目标；一枚下可附任意非负整数积分，但附加总额不得超过本轮结算前余额。
- R08：从第2轮起可用已赢积分加注；不是仅第7轮可加注。第1轮余额0自然不能加注。
- R09：下注时间内可多次替换投注；以服务端截止前最后成功接受的整组投注为准。只有本地编辑、尚未收到确认的操作不算。
- R10（2026-09-22 修订）：获胜作者每人+3，不管是否押自己；重复获胜值作者各+3，不平分。
  等距双胜时两个获胜槽的作者都拿奖，但同一人最多拿一次+3。边缘槽获胜时无人得作者奖（没有人写出那个答案）。
  超时未作答者本轮不在版图上，自然不可能成为作者。
- R11：中奖者各自足额兑付，不瓜分同一奖池；永久筹码不扣余额、不丢失；只有押错的附加积分损失。
- R12：第7轮结算后按余额降序，再按获胜答案次数降序。仍同分的处置见 G0，默认并列获胜，不采集生日。

## 3. 赔率完整查表（禁止重解释“1赔X”）

UI 写“净赢 ×N”并解释“押中返还本金，另获 N 倍收益”。
物理位置定义：L3/L2/L1/C/R1/R2/R3，赔率分别5/4/3/2/3/4/5。两个边缘槽 LOWER / HIGHER 恒为6。

| 不同值数量 | 按升序占用位置 | 对应净赢倍率 |
|---|---|---|
|1|C|2|
|2|L1,R1|3,3|
|3|L1,C,R1|3,2,3|
|4|L2,L1,R1,R2|4,3,3,4|
|5|L2,L1,C,R1,R2|4,3,2,3,4|
|6|L3,L2,L1,R1,R2,R3|5,4,3,3,4,5|

实现 `buildBoard` 使用常量查表，不重新推导复杂公式。稳定目标 ID 用 `g:<数值>`；边缘槽 `lower` / `higher`，分列版图两端。物理位置与目标 ID 分离。
例如10/16/18/20：16和18位于两个3倍位，绝不是18和20。

## 4. 账本唯一算法

状态 `score` 始终表示结算前完整余额；下注保存只计算 reserved，不扣 score。
每枚筹码 `extraStake` 为附加积分，免费基础值1不包含在 extraStake。

```text
reserved = A.extraStake + B.extraStake
available = score - reserved
winProfit = sum((1 + extraStake) * odds(target) for each winning placed chip)  // 等距双胜时各槽用各自赔率
loss = sum(extraStake for each losing placed chip)
authorBonus = 3 if a submitted guess equals any winning guess else 0（同一人最多一次）
scoreAfter = scoreBefore + winProfit - loss + authorBonus
```

未放置筹码的 extraStake 必须为0，无收益无损失。永久筹码拿回仅是视觉表现，不再加1到 score。
赢的附加本金本来就在 scoreBefore，因此**不能再加本金一次**。
若服务端未来改为下注时扣款，将违反本契约，必须单独提出版本变更，不可混用两套公式。

示例：余额10，A在3倍胜位加注4，B在败位加注2，非作者：10+(1+4)*3-2=23；可用余额下注期间是4，不是score=4。
余额0，两枚都押3倍胜位且为作者：0+3+3+3=9。
更完整的多人算例及重复值见 golden-cases.json，不能从被测实现反向生成 expected。

## 5. 数值与题库建议（G0前不视为批准）

- 猜测范围1..999,999,999,999，`Number.isSafeInteger` + 上下界；禁止非整数值、NaN、Infinity和字符串型动作value。UI输入只允许十进制数字，不接受科学计数法、百分号/单位后缀；格式化逗号只用于展示。注意JSON解析后1e3与1000都是整数1000，服务端校验数值语义，不虚假承诺识别原始数值拼写。
- 题目答案同范围；小数题先明确换成整数单位，例如“以厘米计”。不支持答案0或负数的题进入首版题库。
- 积分使用非负安全整数；七轮的宽松上界 `S[r+1] <= 7*S[r]+15`，S0=0，S7<=2,058,855。可以 assert 安全整数，不能溢出后截断或封顶改规则。
- 题库静态离线、人工审核，先7题测试样本，发布建议70题（内容量约10局，但随机抽题默认只保证本局不重复，不承诺跨局10局不重复）。用户未确认数量。
- 每题含 prompt、unit、answer、sourceUrl、sourceNote、asOf、explanation、reviewed、id；动态事实必须限定年份/口径。禁止用模糊“约多少”却没有确定统计口径的答案结算。
- 不抓取或复制受版权保护的整套官方700题及官方美术；编写自有题面，引用可核查事实。模型生成不等于审核通过。
- 发布前所有题目逐条审校，7题测试数据不能标作题库完成。题库中答案及来源仅服务端持有，揭晓后只公开当前题来源。
