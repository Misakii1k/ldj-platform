# 视觉与交互约束（G0 已定方向 / 画面验收待确认）

> **2026-09-20 更新（G0 P6）**：用户选定「**完全复用平台现有浅色纸感体系 + 新 accent**」。
> 原稿的深绿底 `#0B2424` + 米白字方向**已作废**。§1 方向句与 §3 色表按此重写，
> **§2 根结构/断点、§4 三张关键画面、§5 状态矩阵、§6 动效、§7 验收矩阵均不受影响，继续有效。**
> 依据与实测对比度见 `reports/T00-baseline.md` §5。

## 1. 设计方向

“朋友围桌估数”而非赌场充值界面：沿用平台**浅色纸感**底板（与首页/其他游戏同一套 `--game-*` 令牌）、
纸色数字牌、深墨文字、少量实体筹码感。专属识别度由 accent 色与版面结构提供，不靠另起一套配色。
不用3D、不接图片生成服务、不导入官方商标图/版图原画；首版CSS/SVG原创几何装饰即可。
这是布局和风格提案，**还不是用户认可的截图基准**。T07须先提交答题/下注/结算三张关键画面，确认前不得宣称“视觉不偏离”。

## 2. 根结构与尺寸

根类 `.ww-game`，局部类 `.ww-*`，不覆盖body、button或其他游戏选择器。
局部 CSS 变量 `--ww-*` 仅用于**布局量**（间距、卡宽、列数等）；**颜色一律直接引用 §3 的平台 `--game-*` 令牌，不再定义 `--ww-` 颜色变量**（G0 P6）。
复用GamePage的进入/退出沉浸行为；不自建全局全屏副作用。
外壳100dvh（100vh兼容），safe-area四边留白，min-width:0/min-height:0，不允许页面级水平滚动。
顶部状态区固定，中心为唯一主滚动区，底部操作区sticky；抽屉内部可滚动时锁住底层，不出现两个同时抢手势的滚动面板。

允许CSS媒体查询仅宽380/480/640/768/1024/1280，高520/620；测试分辨率不等于新增CSS断点。
桌面>=1024：内容max-width 1280居中，题面与赔率板约3/4宽，右侧榜单240px。七个物理槽+特殊槽可一排，min-width不能挤破容器。
手机<768：题面→状态→板→底部投注编辑器；玩家排名折叠为一行摘要，完整榜单抽屉。
低高横屏（max-height:520）：缩短头部和题面padding、操作区两列，隐藏纯装饰不隐藏单位/倍率/余额/错误。

## 3. 色值（G0 P6 重写：复用平台令牌，不新建 `--ww-*` 调色板）

> 旧版 `--ww-bg #0B2424` 等 9 个深色 token 及其 5 个对比度结论 **SUPERSEDED，不得再引用**。

### 3.1 直接复用的平台令牌（`packages/client/src/styles.css`，不得改写其定义）

|令牌|色值|用途|
|---|---|---|
|--game-paper|#fff4df|数字牌/下注卡底|
|--game-surface|#fffdf7|面板/编辑器底|
|--game-ink|#292722|主文案、数值、倍率|
|--game-muted|#575147|次要文案、单位、作者名|
|--game-line|#292722|卡片描边|
|--game-yellow|#f7c84b|选中/中奖高亮底（配 ink 文字）|
|--game-coral|#c23616|错误与危险实体底（配白字）|

### 3.2 本游戏 accent

catalog 登记 `theme: 'ocean'`、`visualTheme: { accent: 'ocean', surface: 'board' }`。
`ocean` 与 `cyan` 是目前 6 个主题中唯二未被占用的（现有 11 款为 violet×2 / berry×2 / sunset×4 / mint×3），
选 `ocean` 因其深色档对比度余量更大。平台已定义：

```
.game-card--ocean { --game-accent: #237c93; --game-soft: #d5edf2; --game-dark: #115665; }
```

### 3.3 实测对比度与硬约束

| 组合 | 比值 | 结论 |
|---|---|---|
|ink / paper|13.68|✅ 正文|
|ink / surface|14.67|✅ 正文|
|muted / paper|7.20|✅ 正文|
|muted / surface|7.72|✅ 正文|
|ink / yellow|9.46|✅ 正文|
|white / coral|5.48|✅ 正文|
|**white / game-dark `#115665`**|**8.26**|✅ 正文（主按钮用这一组）|
|game-dark / paper|7.57|✅ 正文|
|white / accent `#237c93`|4.80|⚠️ 临界，不用于按钮|
|accent / surface|4.72|⚠️ 临界|
|**accent `#237c93` / paper**|**4.40**|❌ **正文不达标，仅 ≥24px 大字**|

**强制规则：**

1. 纸底（paper/surface）上的正文、数值、倍率、单位、作者名一律 `--game-ink` 或 `--game-muted`；**禁止用 `--game-accent` 作纸底正文色**。
2. accent 仅用于：描边、选中态边框、图标、≥24px 大号标题。
3. **主操作按钮 = `--game-dark` 实底 + 白字（8.26）**；不得用 `--game-accent` 实底。
4. 中奖/选中高亮用 `--game-yellow` 实底 + `--game-ink` 文字（9.46）。
5. 特殊槽（全部猜高 ×6）用 `--game-coral` 实底 + 白字（5.48），与普通槽形成实体区分。
6. `--game-soft #d5edf2` 仅作大面积浅填充（如选中卡背景），其上文字仍须 ink。
7. muted 不用于 yellow / coral / game-dark 等彩底。
8. 禁用按钮不直接 `opacity:0.3`；仍需文字可读，并用“已截止”等文字说明。

上表为 token 层面的数学计算，**不等于浏览器渲染验收**。T07 必须在真实页面的计算样式下核验最终色、覆盖样式、渐变与所有交互状态（AGENTS.md 强制）。

- 字体沿用平台系统中文字体，不下载新字体。
- 正文16px，标签14px，主数字clamp(24px,4vw,40px)；赔率18px粗体，输入24px。
- 所有可点区域>=44×44px；主按钮高48px；数字卡边框2px、圆角12px，间距8/12/16/24px。
- 特殊槽永久保留，可见“全部猜高 / 净赢×6”；不得表现成只在答案公布后才出现的隐藏奖励。
- 玩家用“席位序号+名字+颜色”三重识别，不靠颜色唯一编码；金币图标不可代替分数字样。

## 4. 三个关键画面与验收快照

### V1：秘密作答

```text
一智千金          第2/7题     00:24
┌──────────────────────────┐
│ 题面（最多占据首屏约1/3） │
│ 单位：千米               │
└──────────────────────────┘
我的估数  [      12345      ]
填写正整数；不确定也可以猜。
[ 提交估数 ]
已提交 4/7                 我的积分 10
```

输入框type=text+inputMode=numeric，避免number输入接受e/小数。输入文案明示范围；本地数字草稿不对他人发送。
按钮提交后等待服务端确认；已确认显示“已提交 12,345，可在揭晓前修改”。其他玩家只看到勾选状态，不看到猜测。
说明“所有人提交后立即揭晓”（P3）；不承诺提交后必定还能改。
输入/修改无效不清空用户草稿；屏幕键盘弹出时提交按钮仍可达。

### V2：下注（重点）

桌面按物理槽排列：
```text
[全部猜高×6] [L3×5] [L2×4] [L1×3] [C×2] [R1×3] [R2×4] [R3×5]
```
空位只作浅描边不可点击；偶数时C显示“本轮空位”。
手机不为保留物理对齐把8列缩得无法点击：隐藏无效空槽，只展示升序的有效下注卡，**每卡显示已由服务端给定倍率**，不得依手机位置重算赔率。
手机特殊槽独占一整行，普通有效卡为两列（最大7张，最后一张占满），卡片内：数字、单位短名、倍率、作者、投注小标记。数字极长时缩至24px，不截断成“1.2T”导致不可比较。

底部编辑器：
```text
余额 10   已预留 6   可用 4
[A筹码  已选：300]  附加积分 [-] 4 [+]
[B筹码  已选：200]  附加积分 [-] 2 [+]
[ 保存投注 ]
```

流程严格：选A/B → 点目标卡 → 调整该筹码附加积分 → 保存整组投注。默认A选中。
两个筹码同目标时目标卡显示A+B，不能合并后丢失免费基础值2。
可清除某枚筹码（同时附加归0）；可加1/减1、输入数额、“全部可用”快捷键（指本筹码可用=score-另一枚加注）。不增加1/2/5/10多排快捷按钮。
编辑草稿标“未保存”；保存成功后只以确认投注展示“已保存”。超时/拒绝时保留本地草稿并显式标“未保存”，已保存投注图层只呈现最新确认数据；阶段已切换则丢弃旧阶段草稿。房间版本冲突后同步并提示用户再点保存，不能自动重发改变筹码。
赔率说明用按需展开：“免费筹码值1，附加积分才会亏损；押中净赢=(1+附加积分)×倍率”。
全桌公开投注是当前已保存数据，自己的未保存草稿只在本人编辑器虚线显示。
所有人下注后仍计时到截止（P3），顶部提示“截止前可调整”。

### V3：结算与终局

```text
正确答案       300 千米
获胜估数       300（净赢×3）
题目解释和可展开来源
我的结算
上一轮余额 10
投注盈利   +15
错误加注    -2
估数奖励    +3
当前余额    26
结算展示结束后进入下一轮        查看全部结算
```

每个人都看到自己的增减项，不能只飞几个筹码不显示账本。
“作者奖励”与“押中盈利”不同栏目；本金返还不能显示为额外收益。余额0的玩家仍显示下轮2枚免费筹码。
终局显示score、winningGuesses、排名；并列冠军均高亮。回大厅沿用现有房间权限，普通玩家不可替房主结束其他人的会话。

## 5. 必备状态矩阵

- answering：空值/非法值/编辑/发送中/已接受/截止/他人提交/断线保留/本人退席。
- arranging：按 `arrangingSeconds`（默认 6 秒，可配 3/6/10）展示升序，重复作者叠放但名字可读；无操作按钮；无答案。
- betting：无投注/两枚同处/两枚分开/0附加/全押/余额不足/双标签旧revision/保存失败/倒计时结束。
- settlement：精确命中/全部猜高/无人下注获胜位/多人重复作者/本金全亏到0。
- spectator：相同公开题面与棋盘，无输入、无本人猜测、无下注按钮，显示“观战中”。
- recovering/断线：沿用连接状态提示；禁新发送但允许看旧确认值；不靠本地过期强行切阶段。
- malformed/unknown view：现有GameErrorCard，重同步或回大厅，不渲染未校验数据。

## 6. 动效和资源约束

数字卡入场180ms、排序280ms、中奖高亮300ms、积分数字过渡<=400ms；只transform/opacity，不引入持续流动背景。
阶段展示时长由服务端配置决定：`arrangingSeconds` 默认 6 秒（可配 3/6/10）、`settlementSeconds` 默认 11 秒（可配 8/11/15）。客户端演出总时长必须收敛在 `deadlineAt` 之内，超出时压缩间隔而非延后阶段。
动画结束不是阶段转换信号。刷新、reconnect不重复播放已经看过的结算奖励音效；根据roundToken/phaseEpoch区分。
prefers-reduced-motion或平台低动效档关闭位移动效；document.hidden时无装饰RAF/间隔器。唯一倒计时显示最多每秒更新，切页清理。
首版音效可不做；任何后续音效必须可静音，不自动访问TTS供应商。

## 7. 验收矩阵（不是只截图首页）

在360×800、390×844、768×1024、844×390、1280×800分别检查答题/下注/结算/观战。再用320×568检查极限可达性。
使用固定假题、固定玩家名（含12字长昵称）、7个不同值、7人同值、4不同值、12位数字、0积分、超长题面。
- 竖屏可滚动看齐所有目标，主操作可达；横屏不要求竖屏旋转；无按钮被底部安全区或键盘遮挡。
- 每个目标可点且读出数值/倍率/选中筹码；特殊槽一直可选；空槽不可选。
- 截图在动画静止后采集。锁定浏览器/字体/viewport，基准必须由用户或负责人审核，禁止失败后自动接受新截图。
- 截图比较锁定布局与文案，动态倒计时/名字可用固定fixture；不能把整屏mask掉来通过。
- 对局真实手机多人测试才可标M4；浏览器多尺寸只能支撑M3，不能冒充真机。
